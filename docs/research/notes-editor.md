# 笔记编辑器：怎么做到 Notion 的手感，又让文件还是你的 Markdown

> 状态：v0.2（2026-11-25），研究，给 `docs/design/notes.md` 4.3 / 4.4 / 4.5 / 4.11 / 4.12 用。Bruce 要 Notion 那种感觉（2026-11-25），原型 `prototype/notes.html` v3。
> v0.2：按一次审查补了保存规则（3.1 的"块之间的空行"和"读回来一样"、3.4 的保存协议）、看不懂的写法怎么认（3.1）、Zirma 的输入和修订的锚点（3.3）、待办的来源（3.5）、改名（3.4）、两个字的中文搜索（3.4）；GitLab 那条先例改成【没核实】；测试（第 4 节）重写。
> 标记：**【事实】** 查过资料、读过代码或实测过；**【建议】** 本文的提案；**【没核实】** 动手前要实测。

## 0. 结论

1. **难的不是编辑器，是"存回去"。** 所有块编辑器（Tiptap、Milkdown、BlockNote、Lexical）都能把 Markdown 读进来；但写回去时都是**整篇重新生成**，会顺手改掉你没动过的地方：列表符号、空行、表格的对齐、看不懂的写法。别的 App（Obsidian）打开同一个文件，就会看到一堆不是你改的改动。
2. **所以存取这一层我们自己做：只重写你改过的那几块，其余一个字节都不动。** 读文件时记下每一块在原文里的起止位置；保存时，没改的块原样照抄原文，改过的块才重新生成，再拼回去。**拼完一定再读一遍**：读回来的块（种类、文字、顺序）必须和编辑器里的一样，不一样就不算存好（3.1）。GitLab 的富文本编辑器做过同一件事（藏在 `preserve_unchanged_markdown` 开关后面）；它后来有没有上线、是不是因为大文件太慢、源码位置不准而撤掉，【没核实】。不管怎样，这两点都是 N2 要实测的（第 4 节第 6 条）。
3. **编辑器直接用 ProseMirror**（MIT），不套 Tiptap、Milkdown、BlockNote。界面上的东西（`/` 菜单、选中工具条、把手、Zirma 的修订）我们本来就要按自己的样式做；套一层框架省下的不多，反而隔在我们和存取层之间。
4. **读 Markdown 用 `mdast-util-from-markdown`，加 GFM、属性（frontmatter）、数学三个扩展，再加一个我们自己的 `[[双链]]` 扩展**（unified 那一家都是 MIT）。带每个节点的原文位置。**看不懂的原样留着**：块级的是一块"原样保留"的源码，行内的是一个原样写回的小块。
5. **Zirma 的修订不进文件，只是画在编辑器上的一层。** 修订记着它改的是哪一段、原来是什么字；你点「好」时原文已经变了，这条修订就作废，不会改错地方。
6. **保存一次只走一个，主节点对同一个文件排队。** 每次保存带"打开的是哪个库"和"上一次存成的指纹"；对不上就不写。Obsidian 恰好在同一刻也写了的那一份不丢（3.4）。
7. **不做 CRDT、不做多人同时编辑。** 一台家里的主节点，文件是真相；两边同时改走"别处改过"那条规矩。

## 2. 选项

【事实】除注明外，来自各项目的文档和源码。

| | 是什么 | Markdown 存回去 | 和我们合不合 |
|---|---|---|---|
| **ProseMirror** | 编辑器内核，MIT；Tiptap、Milkdown、BlockNote、Outline 都建在它上面 | 不管，交给你 | 最合：模式（schema）、按键、装饰层都自己定；存取层我们本来就要自己做 |
| **Tiptap v3** | ProseMirror 上的一层，核心 MIT，有 React 绑定 | 官方 `@tiptap/markdown` 还是 beta，用 marked 解析，整篇生成；文档自己建议做往返测试 | 能用；但拖块把手有开源版和付费版两个包，说法不一（【没核实】）；它的好处（现成扩展、现成菜单）我们多半用不上 |
| **Milkdown** | ProseMirror + remark，MIT；Crepe 是带把手和 `/` 菜单的成品 | 整篇经 remark 重新生成；remark 自己说完全一样的往返做不到 | 思路最接近，但 Crepe 依赖 Vue（会把第二个框架带进 React 应用），而且仍然得在它外面再做"只改动过的块" |
| **BlockNote** | 最像 Notion 的成品块编辑器，核心 MPL-2.0 | 官方文档写明 Markdown 导入导出是**有损的**，建议存它自己的 JSON | 不合：违背 R2；另外 xl- 开头的包是 GPL/AGPL 或商业许可 |
| **Lexical** | Meta 的编辑器，MIT | 无损的是它的 JSON；Markdown 靠转换器，往返接近但不完全一样 | 不合 R2 / R3 |
| **CodeMirror 6 实时预览** | Obsidian 的做法：文字就是源码，光标不在时把 Markdown 符号藏起来 | 天生无损，文字就是文件 | 合 R2–R4，但不是 Notion 的手感（光标一到，`**`、`#` 就露出来；块不能拖；待办、折叠、表格都是装饰）。适合以后做一个「源码」模式 |

## 3. 推荐的路线

### 3.1 一页从磁盘到屏幕，再回去

```text
读： .md 字节 ──mdast（带位置）──▶ 顶层块列表 [{种类, 原文起止, 原文, 内容指纹}] ──▶ ProseMirror 文档（每块一个节点，带块号）
写： ProseMirror 文档 ──逐块比──▶ 没改的块：原文照抄
                                  改过的块：只生成这一块的 Markdown
                                  新块 / 删掉的块：插入 / 去掉
                        ──拼回去（块之间的空行见下）──▶ 新的 .md
                        ──再读一遍，和编辑器里的块比──▶ 一样：带库号和上一次的指纹去存（3.4）
                                                       不一样：放宽重写的范围再试；还不一样就不存（见下）
```

- **块的粒度是顶层块**（一段、一个标题、一整个列表项、一个代码块、一张表）。列表按"项"分，这样改一项不会重写整个列表。
- **块之间的空行**。【事实】实测：`# 甲\n乙` 读出来是标题加段落；把标题改成正文、保留原来的单个换行，文件 diff 只有第一行，但再读一遍"甲"和"乙"并成了一段（CommonMark 里段落遇到下一行文字会接着写）。所以规则是【建议】：
  - 两边的块都没改：它们之间的原文（空行、注释之类）照抄。
  - 有一边改过、是新块、或者种类变了：原来那段间隔里已经有空行就照抄；没有就写成一个空行。同一张列表里的相邻项、同一张表的行例外，照列表和表自己的写法。
  - 所以 R3 的说法是"只变改过的块，和它前后必要的空行"。
- **读回来一样**（R3a）：拼好的新文本在存之前用同一个解析器再读一遍，按"种类、纯文字、顺序"和编辑器里的块比。对不上，先把相邻的两块也重新生成再比；还对不上就**不存**：编辑器里的字还在，页顶写"这页没存上"，给「另存一页」（另存走整篇生成，内容不丢），并记一条日志给我们修。这一步在浏览器里做（几千行的页要多久【没核实】，第 4 节第 6 条量）。
- **偏移量**：mdast 的位置是 JS 字符串里的下标（UTF-16），不是字节。拼接全程用字符串下标；读时记下有没有 BOM、换行是 `\n` 还是 `\r\n`、结尾有没有换行，写时照原样还回去。
- **块号只在内存里。** 不往文件里写 id（§4.4 第 4 条）。下次打开按位置重新编号。
- **看不懂的写法怎么认。** 只靠"解析出来不在我们模式里"不够：【事实】实测用 GFM + frontmatter 读 `$$` 包住的多行公式，`a_b*c*d` 里的 `c` 被读成斜体，整块成了一个普通段落；`[[项目|别名]]` 和 `![[图.png]]` 被读成普通文字。这些都不会自己落进 `raw`：用户一改那一段，公式就被重新生成坏了；双链也没进索引。所以【建议】：
  - **读的时候就把这些写法认出来**，而不是事后猜：
    - 数学：加 `micromark-extension-math` + `mdast-util-math`（MIT，同一家）。`$$…$$` 是块，`$…$` 是行内。【事实】加上之后上面那段读成一个 `math` 节点，原文完整。
    - 双链和嵌入：自己写一个小的 micromark 扩展（规则照搬 Robin 的 `obsidian-links.ts`）：`[[目标]]`、`[[目标|别名]]`、`[[目标#标题]]`、`[[目标^块]]`、`![[嵌入]]`；代码里的不算。
    - Obsidian 的其他行内写法：`%%注释%%`、`==高亮==`、行尾的 `^块号`、`#标签`。
  - **块级看不懂的**（HTML 块、Dataview 之类带语言名的代码块、脚注定义、数学块、模式表示不了的嵌套）变成 `raw` 节点：显示成等宽的源码，能直接改文字，保存时写的就是你看到的那段文字，绝不重新生成。数学块先当 `raw` 显示，渲染成公式是以后的事。
  - **行内看不懂的**（行内数学、`%%注释%%`、`^块号`、认不出的 HTML 标签）变成一个原子的行内节点，存着原文，生成这一块时原样吐回去。所以改了公式旁边的一句话，公式一个字也不变。
  - **双链是原子的行内节点**，存目标、别名、标题、嵌入与否，以及原文；没改过就吐原文，改过才按 `[[目标|别名]]` 生成。索引从同一个节点取目标，所以带别名的双链也算"提到"。
- **块内的行内格式**（粗体、斜体、代码、链接）在编辑器里是 mark；生成这一块的 Markdown 时用固定的写法（`**`、`*`、`` ` ``）。只有改过的块会用到，所以你原来写 `__粗__` 的地方不改就不会变成 `**粗**`。
- **属性区（frontmatter）** 单独一块：我们只改自己认识的键（`icon`、`cover`、`created`、`source`、`event`），别的键和注释原样留着。

### 3.2 编辑器（packages/ui，只在打开一页时加载）

【建议】

- 依赖：`prosemirror-model`、`-state`、`-view`、`-transform`、`-commands`、`-keymap`、`-history`、`-inputrules`、`-dropcursor`、`-gapcursor`（全是 MIT，同一个作者）。加上 `mdast-util-from-markdown`、`micromark-extension-gfm` + `mdast-util-gfm`、`micromark-extension-frontmatter` + `mdast-util-frontmatter`、`micromark-extension-math` + `mdast-util-math`。**不用** `mdast-util-to-markdown`：单块的生成很小，自己写，写法我们说了算。
- 模式（schema）：段落、标题 1–3、列表项（无序 / 有序 / 待办，带缩进层级）、引用、提示框（`> [!note]`）、折叠（`<details>`）、代码、分割线、表格（GFM）、图片、链接卡片（单独一行的网址）、子页面链接、`raw`。行内：粗体、斜体、行内代码、删除线、链接、页面链接（`[[ ]]`，原子节点）、原样保留（原子节点）。
- `/` 菜单、`[[` 选页、选中工具条、块左边的「+」和把手：自己做（React 组件挂在编辑器外面，按 ProseMirror 的坐标放位置）。把手拖动用 ProseMirror 的节点选择 + `dropcursor`。
- 行首 Markdown 写法变块：`inputrules`。
- 中文输入法：ProseMirror 处理了组字（composition），组字时不触发 `/` 菜单和行首写法（【没核实】在 macOS 拼音、手机 Safari 上实测，N2 的第一批测试）。
- 在手机上：没有把手，靠 `/` 和选中工具条；键盘上方给一个小的块工具条（以后）。

### 3.3 Zirma 在页面里

【建议】

- **给模型什么。** 一次不带工具的模型调用（和 Links 的 L2 共用一个入口），输入是：
  - **这一页现在的样子**：编辑器里的文档当场生成的 Markdown，**包括还没存的字**，不是磁盘上那份；太长就给标题提纲加光标附近的几块，并告诉模型截了；
  - 你选中的那段（没选就是光标所在的块，或者"整页"）；
  - 你说的话。
  
  所以从空行打 `/问 Zirma` 问整页，模型拿到的是整页，不是一个空块。
- **修订记着改的是哪里。** 回来的修订是"把这段换成什么"或"在哪一块后面加一块"。发问那一刻记下两样：目标在文档里的位置（ProseMirror 的位置，随你之后的每次编辑一起映射），和目标原来的文字。
  - 画：ProseMirror 的 Decoration 画出划掉的字和新字，文档本身没变，所以不会被存。
  - 点「好」时先复核：映射后的范围还在、里面的字和记下的原文一模一样，才把它变成一次普通的编辑事务。不一样（你在等的时候改了那句，或者那段被删了），这条修订作废，原处写"原文改了，这条不用了"，可以再问一次。
  - 你在等回复时编辑了和目标**重叠**的地方：修订马上作废；不重叠的编辑不影响它。
  - 同一段里有两句一样的字：靠位置认，不靠在文字里搜，所以不会改到另一句。
- **Zirma 自己在后台想改一页**（对话里说"把那页的水温改成范围"）：仍是 §4.7 的 `note_edit` 提议，钉住"文件的指纹 + 那一块的原文"。文件在这期间变了：那段原文在页里还恰好只出现一次，就照样画出来；找不到或出现不止一次，提议过期。
- **待办**（规则见 3.5）：「→ 待办」把这一条交给待办模块，带上来源；待办页上那条能点回这一页、这一条。页顶"还有几个待办没放进去"是在客户端算的：这页的待办块里，哪些的来源在待办模块里找不到。

### 3.4 主节点

【建议】

- **库服务**（`packages/server`）：列、读、写（先写临时文件再改名顶上）、比指纹、路径安全（只在库里，解析符号链接后仍在库里）、改名 / 挪动（`名字.md` 和 `名字/` 一起动，失败就退回）、删到 `.trash/`。
- **库号**：每个库建立时给一个随机的库号，存在主节点的设置里，不写进文件夹。换库就换号，索引清掉重建（§4.1）。
- **文件监听**：Node 的 `fs.watch(库, { recursive: true })`，macOS 上走系统的 FSEvents；再加每几分钟比一遍修改时间兜底（网盘同步的文件夹）。变了就让 `note` 模块的 `sync` 跑一遍，只重读变了的文件（§4.3）。
- **保存**（不走操作，§4.11 第二条）：`POST /api/notes/file`，带：
  - `library`：打开这一页时的库号；
  - `path`：库里的相对路径；
  - `base`：**上一次存成的指纹**（刚打开时就是打开时的指纹）；
  - `text`：新正文。

  规矩：
  1. **库号不对就不写**，回 409「库换了」。手机开着库 A 的一页、桌面已经换到库 B，就算 B 里恰好有同路径、同内容的文件，迟到的保存也写不进 B。手机上的字留在编辑器里，给「另存到现在的库」。
  2. **一页同一时间只有一个保存在路上。** 客户端按顺序发：上一个回来了才发下一个，中间攒下的改动合成一次。回来的结果带**新的指纹**，下一次保存就用它当 `base`。所以第一次自动保存之后，第二次不会拿着打开时的旧指纹和自己冲突。
  3. **主节点对同一个文件排队**：按真实路径加一把锁，"比指纹 → 写临时文件 → 顶上 → 算新指纹"在锁里一口气做完。两台设备拿着同一个旧指纹先后到，先到的写进去，后到的一定是 409。
  4. **409 时回磁盘上现在那一份**，客户端给"换成那一份 / 把我的另存一页"，不合并。
  5. **别的 App 恰好在同一刻写**（Obsidian 在"比指纹"和"顶上"之间落盘）：锁管不了外面的进程。所以"顶上"分两步：先把磁盘上那个文件**改名挪到** `.trash/.versions/` 下，再把临时文件改名顶上；挪走的那份算一遍指纹，和 `base` 一样就删掉；不一样就说明有人刚写过：它原样留在那里，这一页当 409 处理（"这篇在别处刚改过"，「换成那一份」就是把挪走的那份放回去）。能保证的是**哪一份字都不丢**；不能保证的是：在挪走和顶上之间的几毫秒里文件不在原处，Obsidian 会不会因此提示"文件被删了"【没核实】，N2 实测。
- **改名**（页面标题就是文件名，见 notes.md §4.3）：一次改名动的东西，顺序固定：
  1. 改 `名字.md` 和 `名字/`（失败就退回，什么都没变）；
  2. 待办模块里来源指向旧路径的那些，换成新路径（3.5）；
  3. 指向它的双链：按 §4.4 第 5 条只改那些短名认不出它了的。每一篇都是一次普通的带指纹的保存（只动那个链接所在的块）。某一篇的指纹对不上（正在别处被改）：**这一篇跳过**，不硬写；改名照样完成，结果写"4 页的链接改好了，1 页没改：它正在被改"，带「再试」。开着那几页的编辑器收到的是普通的"别处改过"。

  不做跨文件的原子提交：改名完成就是完成了，没改的链接显示成虚线（找不到的页），能再试。
- **索引**（`note` 模块的表）：每页的路径、标题、图标、父页、首句、指纹；页面链接（含别名、嵌入）；全文；待办块（给"没放进去的待办"和 Zirma 的回答用）。主节点和浏览器**用同一份解析代码**（放在 `modules/notes/src/markdown/`，纯 TypeScript，不碰 DOM），这样索引看到的块和编辑器看到的块是同一套。
- **搜索**：全文是 FTS5 的三字切分。【事实】实测 `node:sqlite`：正文"今天的会议记录"，搜"会议"0 条，搜"会议记"1 条；`LIKE '%会议%'` 是 1 条。所以照 notes.md §1 已写的规则：**词里有不到三个字的，退回普通的包含匹配**（同一张表的正文列）；三个字以上走三字索引。

### 3.5 待办和笔记的来源

【事实】现在 `todo.add` 不接收来源；`TodoSource.kind` 只有 `calendar` 和 `mail`（`modules/todo/src/types.ts`、`modules/todo/src/index.ts`）。【建议】

- `TodoSource.kind` 加 `note`；`todo.add` 加一个可选的 `source`（只收 `note`，日历和邮件仍走它们自己的路径）。
- `ref` 是 `note:<库号>:<路径>#<文字指纹>:<第几条>`：同一页里文字一样的待办块按从上到下数第几条。这样同页两条"联系客户"，点第二条记的就是第二条。
- **去重**：和日历一样，同一个 `ref` 只会有一条待办。重复点「→ 待办」不会多出一条，只跳到已有那条；那条你已经在待办页删了，再点就重新建（你自己点的，不是自动的）。
- **改名、挪动**：在 Zirma 里做的，3.4 改名的第 2 步一起换路径；在别的 App 里挪的，索引认出是挪动（同指纹换了路径，§4.3）时也换。
- **跳回原文**：打开那一页，按文字指纹和第几条找到那个待办块，滚过去、闪一下。文字改了：在这一页的待办块里找最像的一条（够像才算），找到就跳过去并把 `ref` 换成新的；找不到就在待办上标"原文找不到了"，不猜。
- **知道的弱点**：你在同一页上面又加了一条一模一样的"联系客户"，原来的第二条就成了第三条，`ref` 会对到别的那一条。概率低，接受；测试里写明。

### 3.6 知道的坑

- **块号不落盘**，所以"这一块"的身份跨不过一次外部大改（别的 App 把段落顺序全换了）。待办和后台提议都按文字找，找不到就说找不到，不猜。
- **嵌套很深的列表、列表里套代码块**：整个列表项作为一块，里面的结构交给模式；模式表示不了的就整项变成 `raw`。宁可显示源码，也不改坏。
- **表格**：编辑过的表会被重新对齐（只有被编辑的那张表）。
- **同一页两台设备同时打字**：后存的那台收到 409，走"换成那一份 / 另存一页"。不做合并。
- **改名不是原子的**：链接可能只改了一部分（3.4），会明说哪几页没改。

## 4. 怎么证明它对（N2 的测试）

样本都是自己写的假笔记（不放真实笔记）。

1. **往返不变**：一批样本（Obsidian 的写法、Dataview、HTML、数学、带别名和嵌入的双链、中英文混排、CRLF、BOM、没有结尾换行），读进来再存回去，**每个字节一样**。
2. **只改一处**：对每个样本随机改一块，存回去，`diff` 只在那一块的行上，加上它前后至多各一个空行。
3. **读回来一样**（R3a）：对每个样本随机做一串编辑（改字、改块的种类、插、删、挪），存，再读，块的种类、文字、顺序和编辑器里的一样。专门一条：`# 甲\n乙`，把标题改成正文，读回来仍是两段。
4. **看不懂的不丢**：`raw` 块和行内的原样节点在任何编辑之后都在、字节不变。专门两条：只改公式旁边的一句话，`$$` 公式原文逐字相同；`[[项目|别名]]` 进了索引，"项目"那页显示被它提到。
5. **保存不覆盖**：
   - 存的时候文件已被改：必定 409，磁盘上那份没被换掉；
   - 两个客户端拿同一个 `base` 同时存：一个成功、一个 409；
   - 一个客户端连续自动保存三次：都成功，没有自己和自己冲突；
   - 换库后，旧库那一页迟到的保存：409「库换了」，新库里同路径的文件不变；
   - 在"比指纹"和"顶上"之间插进一次外部写入（测试里用钩子模拟）：外部那份在 `.trash/.versions/` 里原样在，客户端收到 409。
6. **大文件**：一篇几千行的假笔记（中文、长列表、嵌套引用和列表、几张表），量打开、改一处、"读回来一样"、存各要多久；核对改动落的位置和改的那一块一致（源码位置准不准）。
7. **Zirma 的修订**：发问后把原句改了，点「好」不写、显示作废；同一段两句一样的字，修订第二句，改的是第二句；从空行问整页，模型收到的是整页的字（含没存的）。
8. **待办**：同页两条一样的待办点第二条，待办页上那条跳回第二条；连点两次只有一条；改名后跳回还在；改了待办块的文字后跳回找得到。
9. **改名**：有三篇提到它、其中一篇的指纹对不上：改名完成，两篇的链接改了，一篇报出来且文件不变；标题属性 `title` 和文件名不一致的旧笔记，显示的是文件名。
10. **搜索**："会议"能搜到"今天的会议记录"；三字以上走索引。
11. **输入法**：macOS 拼音、手机 Safari 拼音，在行首、在 `/` 后、在列表里、在表格格子里各组一次字。

## 5. 还没核实的

- GitLab 的"保留没改的 Markdown"后来有没有上线、为什么停（第 0 节第 2 条）。
- Tiptap 的拖块把手到底哪个包是 MIT（只在改主意用 Tiptap 时才要紧）。
- ProseMirror 在手机 Safari 上中文输入的表现。
- "读回来一样"那一遍在几千行的页上要多久。
- 保存时文件被挪走的几毫秒，Obsidian 会不会提示文件被删。
- `fs.watch` 递归在一个几千个文件的库上的开销。
- 主节点（一个 Mac 上的后台进程）第一次读写 `~/Documents` 时 macOS 会不会弹权限，弹给谁（notes.md §1 已列）。
