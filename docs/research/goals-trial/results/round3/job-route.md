# 路线：一年内换一份后端工程师的工作

## 别人一般是怎么走到的

我读到的真实经历里，有两种走法在"怎么走"上确实不同。第三种只有零碎的摘要支撑，放在最后的"没找到"里。

### 自己照清单补齐，再出去面

**这条路是什么样** 先弄清岗位要求哪些知识，再自己一块一块学：语言、数据库、一个能跑通的项目，最后背面试题、投简历。这像考前对着考纲复习，复习完才报名。一位自学者的版本是四步：学基础，做入门项目，背真题，投简历 [1]。

**代价** 全靠自律，没人替你判断学得对不对。这份路线出自一位自学者的个人博客，他自己也说"有的东西不能复制"，并且在推广自己的教程 [1]。另一个代价是，你离开原公司之前，手上没有真实的后端工作经历。

**靠什么** 
- 一张按主题排开的后端知识地图：语言、版本管理、数据库、接口、缓存、测试、消息队列、容器、安全等 [2]。地址：https://roadmap.sh/pdfs/roadmaps/backend.pdf 
- 一份带书单和每项学习时间的 Java 路线 [1]。地址：https://www.cnblogs.com/knifeblade/p/17686041.html

**大约多久** 猜测：半年到一年。那位作者自称零基础 5 个月拿到 offer [1]，这是他的个人说法。另有牛客帖子说"自学半年""快满一年"，我只看到摘要 [6]。

### 在现在的公司里转过去

**这条路是什么样** 不换公司，先换岗位：业余学一阵，和主管谈，调到有后端活的团队里边做边学，之后再带着真实经历去换工作。这像先在自家餐厅调去后厨，再拿着后厨的经历去别家应聘。两个例子都是这样：一位做了十年运维的人，业余学习并多次和主管谈，2020 年底获准转岗 [3]。一位客服，业余学写代码，由同事当导师带着转成了后端工程师 [4]。

**代价** 这要看你的公司有没有后端团队、肯不肯放你过去。两个例子都出自对内部转岗友好的公司，不一定适用于你。转过去通常要从初级做起，那位运维说要保持"初学者心态" [3]。

**靠什么** 
- 一位运维转后端者的自述，写了他怎么学、怎么练 [3]。地址：https://dev.to/l2es/opsdev-how-i-turned-backend-dev-after-a-decade-on-the-ops-side-3m57 
- Monzo 社区里一位导师的回帖，提到他们合写过一篇经历文章。我没打开那篇文章，只读了这个帖子 [4]。地址：https://community.monzo.com/t/switching-from-customer-service-representative-to-backend-engineer/136022

**大约多久** 猜测：转岗本身要几个月，之后再积累半年左右真实经历再外出面试。这个时间两个来源都没给出，纯属猜测。

## 眼前这一段（以第一种走法为例）

只铺最前面一段。我没有你的语言、年限、所在地，所以下面的步骤保持通用。

### 第 1 步：先看清要学的范围

**做什么** 打开一张后端知识地图，再在招聘网站上搜"后端开发"，看十来个岗位的要求。把两边都出现的词摘出来，这就是你要学的范围。

**为什么走这一步** 你现在的感觉是"东西太多"。范围一旦被划出来，就从"无穷"变成"一张有限的清单"。先做这步，后面每一步才有边界。

**用什么走** 
- roadmap.sh 的后端图：一眼看到整个领域有哪些块，图上标明顺序并不严格 [2]。https://roadmap.sh/pdfs/roadmaps/backend.pdf 
- 招聘网站的岗位描述：那位自学者就是这样确定要学什么的 [1]。地址见 https://www.cnblogs.com/knifeblade/p/17686041.html

### 第 2 步：选一门语言，把基础学到能写小程序

**做什么** 选一门主力语言，学变量、类、集合、文件读写、异常处理这些基础，并且边学边敲代码。Java 路线给这一段的时间是 1 到 2 个月 [1]。

**为什么走这一步** 这是后面每一块的底。Monzo 的导师说，起步用哪门语言影响不大，语言之间大体相似，学会一门再换更容易 [4]。国内两条经历则分别是 Java 和 Go [1][8]。

**用什么走** 
- 《JAVA开发实战经典》第 1–15 章、第 24 章：Java 路线给的基础书目 [1]。https://www.cnblogs.com/knifeblade/p/17686041.html 
- 那篇文章的作者认为看书比看视频快，但这只是他的看法，也可以选视频 [1]。

### 第 3 步：学 MySQL 和 Redis 的基本用法

**做什么** 装一个 MySQL，一边读一边用工具写查询语句。再装 Redis，用命令行试存、取、设过期时间。Java 路线给 MySQL 约 3 周、Redis 约 2 周 [1]。

**为什么走这一步** 数据怎么存、怎么取快，是后端的日常。你的大图里也说，这是面试最容易暴露差距的地方。

**用什么走** 
- 《MySQL必知必会》：入门数据库的书，作者给了哪些章节可以跳过 [1]。 
- 《Redis开发与运维》第 1–2 章：缓存的入门读物 [1]。 
- 两本书的链接我没有，书目见 https://www.cnblogs.com/knifeblade/p/17686041.html。

### 第 4 步：做一个从请求到数据库跑通的小项目

**做什么** 用你选的语言做一个小服务：接收请求，读写数据库，返回结果，全程不断线。先别加更多技术。Java 路线里这一步约 10 天 [1]。

**为什么走这一步** 有一篇运维转后端的文章说，转行阶段不要学全家桶，先把一条完整链路跑通。我只看了摘要 [7]。项目也是之后面试官追问的材料。

**用什么走** 
- 入门项目教程：那位作者自己的 10 天项目，是 Java 技术栈 [1]。https://www.cnblogs.com/knifeblade/p/17686041.html 
- 一篇"运维转后端 + AI"的经历，讲了完整链路指什么 [7]。https://bbs.csdn.net/weixin_29192211/article/details/100500173

## 后面的段

- 补操作系统与网络，加上线程、并发这类"八股"。
- 把项目加深：加缓存、消息队列，写下出过的故障。
- 刷算法题，一直刷到中等题能写出。
- 练系统设计题和口头讲项目。
- 整理简历，开始投，边面边补。

## 没找到的、不确定的

- 第三种走法，我没有足够来源支撑。牛客上有"边投边补""先学一门再转 Go"的经历 [6][8]，但打开页面时正文没有出来，我只看到摘要，所以没有把它们写成独立的路。
- 两篇经历都不是"已工作多年、一年内换岗"的完整记录。一个是应届生式自学，一个是公司内转岗。
- roadmap.sh 的 backend-beginner 页面能打开，但正文是空的，所以我读的是它的 PDF 总图。另有 roadmap.sh/backend 和 Go 官方入门页，我没有被允许打开。
- 时间都是个人自述。我没找到可靠的统计说明一般要几个月。
- 书单是 Java 路线。Go、Python 等语言的对应书目，我没有读到。
