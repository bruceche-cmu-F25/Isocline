# 世界观：一年内换一份后端工程师的工作

## 整件事
**是什么** 换工作，说白了就是让一家公司相信：交给你一块后端的活，你能做好。后端是用户看不到的那一半，包括数据怎么存、请求怎么处理、系统怎么在人多时不垮。公司靠几轮面试来判断这件事：看简历、问项目、考基础知识、做题、聊系统设计。[1]

**为什么** 公司没法在几小时里看你真做活，只能用简历和面试这几样东西做替代。所以这件事本质上是把你已有的经历和能力，翻译成对方能验证的样子。一年的时间很长，足够把每个环节都走一遍，但信息太多容易乱，先看清有哪几块会有帮助。

## 目标岗位与方向
这一块说明你要去的是什么样的岗位，因为后面所有要准备的东西都从这里来。

### 岗位描述
**是什么** 岗位描述是公司写的招人说明，列出要会的技术和要做的事。同一类岗位里反复出现的技能，就是这个岗位的共同要求。[1]
**为什么** 要准备哪些东西，主要来自两处：岗位明确要求什么，以及你的简历写了什么。所以岗位描述相当于考试大纲。[1]

### 技术方向
**是什么** 后端有不同的技术路线，比如 Java 加 Spring 是国内常见的一条。具体选哪条，由你想去的公司和岗位决定。我读到的资料主要讲 Java 这条线。[1]
**为什么** 不同路线的面试题差别很大。方向不同，要准备的内容也完全不同。

## 简历与项目
这一块是你给对方看的"成绩单"，也是面试官提问的起点。

### 简历
**是什么** 简历是一页纸，写明你做过什么、会什么技术。面试官一般从简历和项目开始问，再顺着里面写到的技术往下追问。[1]
**为什么** 简历上写的每一项都可能被追问，所以它同时划定了你被考的范围。写了"熟悉 Redis"，就要接得住 Redis 的问题。[1]

### 项目经历
**是什么** 项目是你做过的具体事情：给谁用、你负责哪部分、一次请求怎么走、遇到过什么问题。没有工作项目时，二次开发的开源项目或课程项目也能写，重点是你自己改了什么。[1]
**为什么** 项目是把零散知识串起来的线。项目讲不清，背再多原理也接不回自己的经历。数字要有来源，不能编造。[1]

## 后端的基础知识
这一块是面试里最常被直接提问的"知识库"。

### 语言与框架
**是什么** 包括语言本身（如 Java 的基础、集合、并发）和常用框架（如 Spring、MyBatis）。[1]
**为什么** 日常写后端就是用它们，所以面试官用它们检验你是不是真的写过代码。

### 数据库与缓存
**是什么** 数据库（如 MySQL）负责把数据可靠地存下来，缓存（如 Redis）把常用数据放在更快的地方。就像仓库和柜台上的小货架。[1]
**为什么** 后端系统的速度和正确性，很大程度取决于数据怎么存、怎么取。所以这是最常被问的部分，索引、事务、缓存失效都是重点。[1]

### 计算机基础
**是什么** 包括网络（比如 HTTP、TCP）、操作系统（进程与线程等）和数据结构。[1]
**为什么** 这是所有后端技术的地基。资料说，深度由岗位和面试流程决定。[1]

## 算法与手写代码
这一块是面试里"现场做题"的部分。

### 算法题
**是什么** 算法题是给一道题，限时写出代码，常见类型有二分、双指针、搜索、动态规划等。[1]
**为什么** 有些岗位会有笔试或代码面，用它来快速比较候选人。资料建议有这类要求时要持续练习，不要最后突击；不考的岗位则可以少花时间。[1]

## 系统设计与进阶
这一块考的是"你能不能设计"，而不只是"你知道什么"。

### 系统设计题
**是什么** 比如"设计一个短链系统""设计秒杀"。回答时先问清用户量和要求，再给出基础方案，之后随着流量和故障要求逐步调整。[1]
**为什么** 面试官借此看你的取舍能力。有文章认为，近年各轮面试里系统设计的比重在上升，不过那篇偏重北美大公司，国内情况可能不同。[2]

### 分布式与高可用
**是什么** 当系统拆成多个服务时会出现的问题：消息队列、分布式锁、限流、故障时怎么止损。[1]
**为什么** 是否需要准备，要看简历和岗位有没有写到。写了就要能扛住追问；没写，掌握常见问题就够了。[1]

### 线上问题排查
**是什么** 系统出问题时，比如 CPU 飙高或内存溢出，你怎么发现、定位、修复。[1]
**为什么** 这直接体现你在真实环境里的经验，所以简历提到调优或岗位强调线上问题时会被重点问。[1]

## 面试这件事本身
这一块是整个流程的运转方式。

### 面试流程
**是什么** 通常先筛简历和做题，之后几轮技术面：一面偏基础，二面深挖项目，后面是系统设计，最后聊软素质和业务理解。[3]
**为什么** 每一轮看的东西不同，所以不同阶段要准备的重点也不同。这份流程出自个人复盘，不同公司会有差别。[3]

### 复盘与表达
**是什么** "看过"和"面试时能答"差得很远。能脱稿说出来、能被追问、能落到项目上，才算会。每场面试后记下答不好的题，用来调整接下来的准备。[1]
**为什么** 面试是口头表达的场合，只读不说，真到现场就会卡住。复盘能让要准备的范围逐渐变小。[1]
