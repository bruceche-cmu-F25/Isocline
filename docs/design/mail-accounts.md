# 多个邮箱：先把多个 Gmail 做完整，再接别家

> 状态：草案 v0.1（2026-11-21），**尚未批准**，没有据此改代码。
> 依据：本仓库的 `modules/mail`、`packages/server/src/google.ts`、`google-service.ts`、`packages/module-kit`、`packages/ui/src/Mail.tsx`、`NewMail.tsx`、`SourceBar.tsx`、`Accounts.tsx`；`docs/design/settings-and-connections.md`；Gmail API 和 Microsoft 的官方文档（2026-11-21 读，链接在文末）。
> 标记：**【事实】** 读代码或文档核实过；**【建议】** 本草案的提案；**【没核实】** 凭已有了解写的，动手前要查；**【待定】** 见第 7 节。

## 0. 结论

1. **「多邮箱」是三件事，难度差很多。** 多个 Gmail 账号；一个账号的多个发件地址；Google 以外的邮箱。
2. **多个 Gmail 账号，底层已经能用。** 连接、存储、同步、发信都是按账号分开的。缺的是界面和 Alfred 的工具：看不出一封信是哪个邮箱的，新邮件从哪发是按字母排的。补齐它是第一刀，不加依赖。
3. **发件地址（别名）便宜，第二刀做。** Gmail 现有的「读」权限就能列出别名。配合「别的邮箱转发到 Gmail」，不接别家也能读和回别家的信。
4. **接别家要先抽一层「邮箱提供方」。** 现在邮件模块直接调 Gmail。抽出来以后，先做 IMAP + SMTP（一个适配器覆盖 iCloud、QQ、163、Fastmail 和多数学校、公司邮箱），再做 Outlook（只能走微软的 OAuth，要注册一个 Alfred 自己的应用）。
5. **规矩不变。** 发信永远走提议，你点头才发；你可以在 Mail 中手动归档单封 Gmail 邮件，助手不能自行归档或删信；邮件里的字是别人的话，不是指令。

## 1. 现在到哪了

【事实】

- **连接**：设置 → 账户里可以连多个 Google 账号（「再连一个 Google 账号」）。每个账号的 token 单独存在钥匙串（`google:<邮箱>`），账号列表在 `connections.json`。
- **存储**：`mail_messages` 的主键是「账号 + 邮件 id」；`mail_sources` 一个账号一行，记着能不能读、能不能发、能不能同步星标和归档、上次读的时间和错误。
- **同步**：`syncMail` 轮询所有连着的账号，一个账号出错不影响别的。每个账号读最近 14 天的收件箱，最多 500 封，每 30 分钟一次。
- **发信**：发信的内容里带着账号。回信从收到原信的那个账号发。新邮件的编辑器里，能发信的账号多于一个时已经有发件人下拉框（`NewMail.tsx`）。
- **缺口**：

  | 缺口 | 位置 |
  |---|---|
  | 邮件列表的行上不显示是哪个邮箱的，也不能只看一个邮箱 | `packages/ui/src/Mail.tsx` |
  | 来源栏只说第一个出错的账号（账号名藏在悬停提示里）和最新一次读的时间 | `packages/ui/src/SourceBar.tsx` |
  | `mail_list` 给 Alfred 的结果不带账号，也不能按账号查 | `modules/mail/src/index.ts` |
  | Alfred 写新邮件时，发件账号固定是字母序第一个，它没法选；你自己写新邮件时默认的也是这一个 | `modules/mail/src/write.ts:107`、`Mail.tsx:529` |
  | 发信的提议卡上不写从哪个邮箱发 | `modules/mail/src/write.ts`（`SAY`） |
  | `mail_read` 只按邮件 id 找，不带账号。Gmail 的 id 是每个邮箱自己编的，两个邮箱理论上会撞 | `modules/mail/src/index.ts`（`getMail`） |
  | 待办里「从哪封信来的」只记了邮件 id，没记账号 | `modules/todo/src/index.ts:209` |
  | 账号没有名字，只有邮箱地址。两个地址 `@` 前面一样时很难一眼分开 | `packages/protocol`（`GoogleAccount`） |

- **Gmail 专用的地方**（接别家时要动的）：
  - 模块能拿到的外部服务只有 `google`，它给的是「带着 token 发一个 HTTP 请求」（`module-kit` 的 `GoogleService`）。
  - 分类（主要、推广、社交、更新、论坛）和「重要」是 Gmail 的标签；库里对分类有 CHECK 约束。
  - 每封信的 `link` 是 Gmail 网页版的地址。
  - 星标同步更新 Gmail 的 `STARRED` 标签，手动归档移除所选邮件的 `INBOX` 标签。
  - 设置里的三个开关（读、同步星标和归档、替你发）对应的是 Google 的三组权限。
- **Gmail 的别名**：`users.settings.sendAs.list` 接受 `gmail.readonly`，也就是 Alfred 已经在要的「读」权限。它返回账号本身的地址和所有别名，别名带一个验证状态（`accepted` 或 `pending`）。
- **Outlook.com**：2024-09-16 起不再接受用密码登录 IMAP 和 POP，只能走 OAuth。
- **Gmail 自己的「代收其他邮箱」在关停**：新用户 2026 年第一季度后没有，老用户到 2027 年 1 月。对方邮箱自己的「自动转发」不受影响。
- **库**：`imapflow`（IMAP 客户端）和 `mailparser` 是 MIT；`postal-mime` 是 MIT-0。
- 设置文档第 6 节里写着「不做 iCloud / Outlook 账户」。这份草案的 M3、M4 要推翻其中邮件的那一半（第 7 节第 6 条）。

【没核实】

- 以上都是读代码得出的，**没有用两个真实账号跑过**。M1 的第一步就是连上两个账号看一遍。
- 用 `messages.send` 发信时，把 From 写成一个已验证的别名，Gmail 会不会照发。文档没写清楚，M2 开工前先实测。
- 各家 IMAP / SMTP 的地址和端口、哪家要「专用密码」或「授权码」（4.4 的表）。
- 163 / 126 要求客户端先报身份（IMAP `ID` 命令），不报会被拒。
- 用 SMTP 发出去的信，哪几家会自动存进「已发送」，哪几家要客户端自己存。
- 微软那边：学校和公司的账号要不要管理员同意；桌面应用的 refresh token 多久过期。
- `nodemailer` 的许可证（印象是 MIT-0）。
- Google「未验证应用 100 人上限」是不是按连过的账号算。是的话，一个人连三个账号占三个名额。

## 2. 从需求出发

你说「多个邮箱」的时候，想的是下面三件事之一：

| 你想的是 | 例子 | 需要 |
|---|---|---|
| 我有不止一个邮箱，想在一个地方看 | 学校的、个人的 | 每个邮箱都读进来；看得出每封信是哪个的；能只看一个 |
| 回信和写信要从对的那个地址出去 | 学校的事用学校邮箱回 | 回信跟着原信走；新邮件有一个说得清的默认；Alfred 也知道该用哪个 |
| 我的邮箱不是 Gmail | iCloud、QQ、Outlook、公司邮箱 | Google 以外的接法 |

前两件，Gmail 之间已经差不多了，差的是「看得出」和「说得清」。第三件是新东西。

还有一条捷径不用写代码：**让别的邮箱自动转发到 Gmail。** 信就进了 Gmail，Alfred 照常读。缺的只有「从原来那个地址回信」，这正是别名（M2）补上的。所以 M1 + M2 做完，不接别家也能覆盖一部分第三件事。

## 3. 通用语言

| 词 | 含义 | 不是 |
|---|---|---|
| 邮箱（mailbox） | 一个连上的收信的地方，用它的地址认它。界面上只说「邮箱」 | 不是「账号」：一个 Google 账号连上后，日历和邮箱是它的两样东西 |
| 名字 | 你给一个邮箱起的短称呼，比如「学校」「个人」。行上的标签、筛选、Alfred 说话时都用它 | 不是邮箱地址；不是显示给收件人看的名字 |
| 发件地址 | 一封信的 From。一个邮箱至少有一个（它自己的地址），有别名时有多个 | 不是另一个邮箱：别名收到的信还是进同一个邮箱 |
| 默认发件 | 写新邮件、又没说从哪发时用的那个发件地址。全局只有一个 | 不管回信：回信跟着原信 |
| 提供方（provider） | 邮箱背后是谁家的接法：`gmail`、`imap`、`graph`（微软）。只出现在代码和设置页的图标上 | 不是用户要懂的词 |

## 4. 方案

### 4.1 多个 Gmail：界面

【建议】

**只连了一个邮箱时，邮件页和现在一模一样。** 下面这些只在能读的邮箱有两个以上时出现。

- **合在一起看。** 收件箱还是所有邮箱按时间排成一列。「今天」页上的邮件数也是合起来的，不拆。
- **行上有一个名字标签**，放在时间旁边（现在放「草稿」「已回」标签的地方）。字是邮箱的名字，样子是最淡的那一档，不上颜色：颜色在 Alfred 里是领域的意思，不再给邮箱一套。
- **筛选栏多一个下拉框**，在分类旁边：「全部邮箱｜学校｜个人」。筛选栏按页面那一列的宽度换行，窄的时候两个下拉框各占一行，不叠字。
- **来源栏说清是谁。** 都正常时：「2 个邮箱 · 14:05 读过」。有一个出错时点名：「学校 读不到：…」或「学校 要重新连接」。
- **读信的那一面**，收件人那行已经显示地址，不用再加。

**名字从哪来。** 连上时 Alfred 先猜一个：地址里 `@` 后面的第一段（`gmail`、`andrew`）；两个邮箱猜出来一样时，改用 `@` 前面那段。设置 → 账户里每个账号那一行可以改。名字存在连接上（`GoogleAccount.name`），日历页以后要分账号时用同一个。

**默认发件。** 设置 → 账户里，能发信的邮箱中有一个带「默认发件」的记号，点别的那一行就换过去。存成一条用户设置。没设过时，取最早连上的那个能发信的邮箱，不再按字母排。

**提议卡。** 能发信的邮箱多于一个时，发信提议的正文第一行写「发件人：…」。

### 4.2 多个 Gmail：Alfred 的工具

【建议】

- `mail_list`：两个以上邮箱时，每行末尾带上邮箱的名字；加一个参数 `mailbox`（名字或地址），只查一个邮箱。
- `mail_read`：加可选的 `mailbox`。同一个 id 在两个邮箱里都有时，不猜，回一句「这个 id 在学校和个人里都有，说一下是哪个」。
- `mail_send`：加可选的 `from`（名字或地址）。怎么定发件：
  1. 是回信：从收到原信的邮箱发（现在就是这样）；
  2. 给了 `from`、它又能发信：用它；
  3. 否则用默认发件。
- 写给模型的那段说明加一句：有多个邮箱时，新邮件从默认的那个发，除非用户点名；拿不准时照默认的写，提议卡上有发件人，用户能改。这样它不用为了「从哪发」来问你。
- 待办的「从哪封信来的」：新记的写成 `mail:<邮箱>:<邮件 id>`；以前只有 id 的照认。

### 4.3 发件地址（别名）

【建议】

- 同步时，对每个能读的 Gmail 邮箱多问一次 `sendAs.list`，把状态是 `accepted` 的地址存在这个邮箱名下。不多要权限。
- 发件人下拉框里列的是发件地址，不是邮箱：`me@school.edu`、`me@alias.com`（学校）。发信的内容里除了邮箱，多带一个 `from`。
- **回信用哪个地址**：原信是寄给哪个地址的，就用哪个回（原信的收件人里有这个邮箱的某个发件地址）；对不上时用邮箱自己的地址。Gmail 网页版有同样的选项，叫「用收信的那个地址回复」。
- 默认发件的记号也落在发件地址上。
- 只开了「替你发」、没开「读」的邮箱列不了别名，就只有它自己的地址。

开工前先实测【没核实】里的那一条：From 写成别名，Gmail 照不照发。不照发的话这一刀不做，文档改回来。

### 4.4 提供方这一层，和 IMAP + SMTP

【建议】

**密码和连接归主节点，模块只拿到一个登录好的会话。** 这和 Google 现在的分法一样：模块从来看不到 token，只拿到「替这个账号发请求」的东西。

- 主节点加一个「邮箱连接」，和 Google 连接并排：账号列表在 `connections.json` 的 `mail` 下（地址、提供方、服务器、名字，没有密码），密码在钥匙串 `mail:<地址>`。
- `module-kit` 加一个和提供方无关的会话，只有四个动作：

  | 动作 | 说明 |
  |---|---|
  | 读收件箱 | 最近 14 天、最多 500 封，和 Gmail 同一个窗口。回来的是统一的一行：谁寄的、主题、正文、未读、星标、附件名 |
  | 读一封信的线索头 | `Message-ID` 和 `References`，回信时用，好让各家邮箱都把它们串在一起 |
  | 改星标 | 没开这项时不调 |
  | 发一封信 | 收下一封写好的 RFC 822 信；现在的 `buildRaw` 已经在写这个 |

- Gmail 是这个会话的第一个实现，把现在 `modules/mail/src/google.ts`、`write.ts`、`favorites.ts` 里调 Gmail 的部分收进去。模块其余部分（表、同步的对账、工具、提议）不再出现 Gmail 的地址。
- IMAP + SMTP 是第二个实现：`imapflow` 读，SMTP 发，MIME 解析用 `postal-mime`，HTML 转文字用模块里已有的 `stripHtml`。新依赖记进 `THIRD-PARTY-NOTICES.md`。

**数据怎么对上。**

| 现在（Gmail） | IMAP 邮箱 |
|---|---|
| 邮件 id | `<UIDVALIDITY>-<UID>`，只有字母、数字和连字符，现有的 id 规则装得下 |
| 线索 id | 没有统一的；用这封信自己的 id。串信靠 `Message-ID` 头，不靠它 |
| 未读 | 没有 `\Seen` 标记 |
| 星标 | `\Flagged` 标记 |
| 重要 | 没有，一律否。「重要」筛选里不会有这些信 |
| 分类 | 没有，一律算「主要」 |
| 「在 Gmail 里打开」 | 没有。`link` 改成可以为空，为空时界面不显示那个按钮 |
| 发出去的信进「已发送」 | 要看各家【没核实】；不自动存的，发完用 IMAP 存一份进去 |

`mail_sources` 加一列提供方（已有的行是 `gmail`）。**一个地址只能连一次**：已经用 Google 连上的地址，不能再用 IMAP 连一遍。

**连接的过程，照着第一次用的人来写。**

1. 设置 → 账户 → 「加一个邮箱」，下面是一排平铺的选项，各带自己的图标：Google、Outlook、iCloud、QQ、163、Fastmail、其它。
2. 选了 iCloud / QQ / 163 这类：一张卡片，三行字说清「去哪拿专用密码」，一个按钮打开那家的页面；下面两个框，地址和专用密码。不让人填服务器和端口。
3. 选了「其它」：多两行，收信服务器和发信服务器。
4. 点「连接」时 Alfred 先真的登录一次（IMAP 和 SMTP 都试），通了才存。不通时用人话说哪一步没通：地址或密码不对、这家要先在网页上打开 IMAP、连不上服务器。
5. 开关和 Google 的一样三个：读、同步星标、替你发。默认只开「读」。

预设表【没核实，动手前逐家查官方页面】：

| 邮箱 | 收信 | 发信 | 密码 |
|---|---|---|---|
| iCloud | `imap.mail.me.com:993` | `smtp.mail.me.com:587` | App 专用密码 |
| QQ | `imap.qq.com:993` | `smtp.qq.com:465` | 授权码，要先在网页上打开 IMAP |
| 163 | `imap.163.com:993` | `smtp.163.com:465` | 授权码，要先在网页上打开 IMAP |
| Fastmail | `imap.fastmail.com:993` | `smtp.fastmail.com:465` | App 密码 |

**安全。**

- 只连加密的端口；服务器的证书不对就不连，不给「忽略」的选项。
- 密码只进钥匙串，不进 `connections.json`、不进事件、不发给任何设备。
- **加 IMAP 邮箱只能在 Mac 本机上做**（第 7 节第 7 条）：密码不该从手机经远程通道传过来。别的设备上看得到这些邮箱，改不了。
- IMAP 上 Alfred 只做三件事：读、改 `\Flagged`（开了才做）、往「已发送」存一份。不删、不移动、不标已读。

### 4.5 Outlook

【建议】

- 走 Microsoft Graph 的 OAuth，过程和 Google 的那套同形：主节点在本机起一次性的回调、PKCE、refresh token 进钥匙串。
- 要一个 Alfred 自己的微软应用（在 Azure 里注册，类型是公共客户端，个人账号和单位账号都收）。这一步要你来做，和当初建 Google 客户端一样。
- 权限：读信、发信、离线访问；同步星标另要一组，开了才要。
- 对应关系比 IMAP 好【没核实】：Graph 有「重点 / 其他」（对上主要 / 其它分类）、有「重要性」、有旗标（对上星标）、每封信有网页版的地址（对上 `link`）。

### 4.6 设置页

【建议】

- M1：每个 Google 账号那一行多一个能改的名字；能发信的邮箱里有一个「默认发件」的记号。别的不动。
- M3 起：页面底部的「再连一个 Google 账号」变成「加一个邮箱」和 4.4 的那排选项。Google 账号还是一个账号带日历和邮箱两组开关；别家的邮箱只有邮箱那三个开关。

## 5. 分几刀

每一刀做完都能单独用。

1. **M1 多个 Gmail 补齐。** 先连上两个真实账号，把第 1 节的事实跑一遍。然后：名字、行上的标签、按邮箱筛选、来源栏点名、默认发件、提议卡写发件人、三个工具带上邮箱、待办的来源带上邮箱。不加依赖，不改邮件的表：名字存在连接上，默认发件存在用户设置里。
   - 做完的样子：两个邮箱的信混排时一眼分得开；让 Alfred「用学校邮箱给某人写封信」，提议卡上的发件人是学校的；只有一个邮箱的人看不出任何变化。
   - 检查：窄宽度下中文和英文都不叠字。
2. **M2 发件地址。** 先实测 From。然后：同步别名、下拉框列发件地址、回信跟着原信的收件地址、默认发件落到地址上。
   - 做完的样子：一封转发进 Gmail 的别家来信，回信从别家那个地址出去。
3. **M3 提供方这一层和 IMAP + SMTP。** 先只抽层、不加新提供方，Gmail 的测试全过，这是单独的一个提交。再加邮箱连接、IMAP 适配器、「加一个邮箱」的界面和预设。
   - 做完的样子：一个 iCloud 或 QQ 邮箱，照卡片上的三行字连上，读得到信、回得了信、已发送里有那封回信。
4. **M4 Outlook。** 等你注册好应用。

如果你自己要连的都是 Google 的邮箱，M1 和 M2 做完就可以停；M3、M4 是给开源以后别的用户的，什么时候做看那时的需要。

## 6. 这一轮不做

- 不做别家的日历。这份只管邮件；日历仍然只有 Google。
- 不做收件箱以外的文件夹，不做全部历史邮件。还是最近 14 天的收件箱，加上见过的星标和重要。
- 批量归档、删信、移动到其他文件夹和向服务器同步已读状态仍在范围之外。
- 不做 IMAP 的即时推送（IDLE）。还是每 30 分钟读一次，加上手动的「再读一次」。
- 不做附件的读和发。
- 不做每个邮箱各自的签名。
- 不做 Exchange 的老协议（EWS、ActiveSync）、POP、JMAP。
- 不给每个邮箱分颜色。
- 不做「按邮箱分开的几个收件箱页」。

## 7. 需要你决定

每条都有建议；不改就按建议做。

| # | 问题 | 建议 | 影响 |
|---|---|---|---|
| 1 | 多个邮箱的信合在一起看，还是一个邮箱一页 | 合在一起，筛选里能只看一个 | 邮件页的布局；「今天」上的邮件数拆不拆 |
| 2 | 行上怎么标是哪个邮箱 | 一个最淡的文字标签，写邮箱的名字；只有一个邮箱时不出现；不上颜色 | 列表的密度；要不要给邮箱起名字 |
| 3 | 新邮件默认从哪发 | 设置里的「默认发件」，没设过时是最早连上的那个；回信永远跟着原信 | Alfred 会不会为「从哪发」来问你 |
| 4 | 别名（M2）做不做 | 做。便宜，而且配合「转发到 Gmail」能先顶上别家的邮箱 | M3 可以往后放多久 |
| 5 | Google 以外先做哪条 | 先 IMAP + SMTP（一个适配器覆盖多家），后 Outlook（要你去注册应用） | 你自己有没有非 Google 的邮箱要连，决定 M3、M4 的先后和急不急 |
| 6 | 推翻设置文档里的「不做 iCloud / Outlook 账户」 | 只推翻邮件这一半；日历照旧只有 Google | 设置文档那一行要跟着改 |
| 7 | IMAP 邮箱只能在 Mac 本机上加 | 是。密码不经远程通道 | 只用手机的人加不了，要回到 Mac 上 |
| 8 | 名字由 Alfred 先猜一个，还是连接时就问你 | 先猜，设置里能改；不在连接的过程里多问一步 | 连接多不多一步 |
