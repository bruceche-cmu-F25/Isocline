## 0. 结论

1. **加一页「今天」，它是主场。** Alfred 像秘书一样写给你：下一件是什么、几点、链接在哪；今天来了多少邮件、哪几封可能要回；今天做什么、什么时候做；学什么；在办和刚办完的。打开 Alfred 默认落在这页。
2. **通知页变窄。** 只放「Alfred 自己的事在等你」。外面来的事（邮件、截止日、日程冲突）是信息，归「今天」和各自的页面。
3. **Alfred 只告诉，不替你准备。** 一封信可能要回，它说一句、给链接。你开口了它才起草。
4. **问名字挪到首次引导。** 第一次打开 Alfred 时全屏走一遍：名字、模型、Google、早上几点写「今天」，最后形象带着在真界面上走一圈。通知页前面的问候去掉。

## 1. 为什么改

**通知页现在大部分时间是空的，有东西时多半不需要你。**【事实】你本机 11-18 到 11-20 三天的数据：

| 通知种类 | 条数 | 说明 |
| --- | --- | --- |
| 欢迎回来 | 21 | 其中 20 条什么都没带 |
| 任务结果 | 17 | 只有 1 条是明确要送进通知页的 |
| 任务的提问 | 2 | 都在弹出的窗口里几分钟内答掉 |
| 提议 | 1 | 当场拒绝 |

真正要你的事三天 3 件，没有一件靠通知页处理。你的原话：「任务回复状态在这里，感觉有用，但不多。」

**在界面上实际看到的问题**【事实】（演示数据，2026-11-20）：

1. 进门先问名字或问候 5 秒，4 件等你的事被挡在后面。
2. 一句话的结果（「好，加上了，放在今天」）占一整页，要点「知道了」才走。
3. 正看着通知列表时，底下又弹卡片说同一条。
4. 同一个提议的三个版本各占一行。
5. 邮件客户端式的左右分栏：每件事都要点开才能决定。

**你要的是另一样东西。** 原话：「这里是我最值得注意力的地方，给我 brief 的地方，像我的秘书一样告诉我下一件是什么，什么时候发生，链接是什么。」通知页是一个「待处理」的清单，装不下这个。

## 2. 三个地方，一条界线

| 地方 | 回答什么 | 谁写的 |
| --- | --- | --- |
| **今天** | 现在该注意什么、下一件是什么、入口在哪 | Alfred 写给你 |
| **通知** | Alfred 的哪些事卡在你这里 | Alfred 的任务产生 |
| **邮件、日程、待办……** | 那样东西本身 | 外面来的，或你自己的 |

**判断一件事进不进通知，问一句：如果没有 Alfred，这件事还在吗？**【已定】

- 还在：一封要回的信、一个截止日、两个日程撞了。这是信息，「今天」提一句，给链接，在它自己的页面上处理。
- 不在了：Alfred 的任务在等你回答、你让它准备的改动等你点头、它办的事没办成。这才进通知。

| 例子 | 放哪 |
| --- | --- |
| 周老师来信问周四能不能开会 | 「今天」：可能要回，一句理由，点开是那封信 |
| 你在那封信下点了「起草回复」，草稿写好了 | 那封信下面；同时算一件「等你」（你让它写的） |
| 财务邮件里写了 11/25 截止 | 待办页上一条虚线的建议；「今天」提一句 |
| 订票任务问你换哪一班 | 通知，排最前 |
| 邮件发出去了没有，Gmail 没给准话 | 通知 |
| 开发会话办完了 | 「今天」的「刚办完」 |
| 你说过「做完通知我」的报告 | 「今天」的「刚办完」，点开就读 |

## 3. 「今天」

### 3.1 从上到下

一页便条，不是仪表盘（[style.md](style.md) 第 12 节不做仪表盘网格）。一栏，从上往下读：

1. **第一行**：一句问候带下一件事。「早上好。下一件是 10:00 的组会，还有 1 小时 50 分。」【已定：问候在这里，不再有进门的问候】
2. **下一件**：标题、钟点、还有多久，一个主入口（会议链接、文档、那封信）。
3. **等你**：通知里最急的 2–3 件，当场能决定；多的写「还有 N 件」进通知页。【已定】没有就不出现这一段。
4. **今天**：日程和待办排在一条时间线上。没钟点的待办由 Alfred 建议一个时间（见 3.4）。
5. **邮件**：今天来了几封；可能要回的几封，每封一句为什么，点开是邮件页的那封信。不写草稿。【已定】
6. **学习**：今天学什么，入口备好（见 3.5）。
7. **在办 / 刚办完**：正在跑的任务和会话；办完的带直达链接，看过变淡。【已定】

每一行都能点：去那个日程、那封信、那条待办、那个会话。「入口都列好，links 都准备好」是这页的验收标准。

### 3.1b 重想：一句、一条线、一行（2026-11-20 晚，原型做了，等你看）

你看了做出来的 T1 之后说：方向对，但是杂，不直观。还要它在最上面，在工作区上面。原型：[prototype/alfred.html](../../prototype/alfred.html)。**你已经点头（2026-11-20 夜）：以这一节为准，3.1 留作当时的想法。**

**T1 为什么杂**【事实：数的是 `Today.tsx` 在演示数据上的样子】：

- 七个小节，按东西从哪来分（等你、待办、明天、邮件、在办、刚办完）。侧栏已经是这么分的，这一页等于把侧栏又抄了一遍。
- 每个小节有自己的标题、自己右边的链接、自己的一种行：卡片、圆圈行、时间线行、一行灰字、带钟的行。眼睛每到一节要重新学一次怎么读。
- 空的小节也占地方：「今天没有新邮件」「现在没有在办的」。
- 没有一个最重的东西。第一行说了下一件，下面每一节又各说一遍。

**改成四样，一样比一样看得细：**

| | 是什么 | 读它要多久 |
| --- | --- | --- |
| 一句 | 下一件是什么、还有多久，下面是它的门（会议链接、文档） | 两秒 |
| 一条线 | 这一天按先后排，**所有的行一个样子**：什么时候 · 哪一类 · 什么事和一句为什么 · 门 | 十秒 |
| 一行 | 剩下的都是数字：今天几封信、几件在办、几件刚办完、几件逾期。点一个数字，在原地展开 | 要看才看 |

- 一条线上只有三个记号：「现在」、「今天之内」（没钟点的）、「明天」。等你的事排在「现在」下面，点开就在原地决定。过去的折成一行「已经过去的 N 件」。晚上不用另一套版式：今天的折起来，明天顺着同一条线接下去。
- 哪一类用一个带颜色的小图标说（日历、待办的圆圈、信、等你的三角、书），不用小节标题说。
- 没有的东西不出现。没有等你的事就没有那几行，没有在办的就没有那个数字。
- 建议的钟点画虚线，点一下才进日历（3.4 不变）。

**它在哪**【已定，2026-11-20 夜】：侧栏的最上面，单独一行，在「工作台」那个小标题上面。不管侧栏现在是「日常」还是「开发」，它都在那里；点它不换侧栏。它不是一个工作区，是 Alfred 对所有工作区写的那张便条，开发会话办完了也写在这里。打开 App 落在这一页。页名还叫「今天」，图标是 Alfred 自己的标记：正超立方体，直接从形象的几何里取（`markSegments`），不是另画的一个立方体。屏幕上会动的形象仍然只有底下那一个。先试过放在顶栏开关的第一格（原型里也是那样），你在真 App 里看了之后说放在左边最上面更自然，改了。

**做进 App 了**（2026-11-20 夜，你说「照这个原型做进 app」）：

- 页面：`Today.tsx`、`today.css` 整个重写成一句、一条线、一行；`shell/today.ts` 多了 `todayLine`，把读模型排成一条线上的行，有测试。

**和原型的差距**（2026-11-21 补了三项）：

| 原型里 | App 里现在 |
| --- | --- |
| 等你的事点开在原地决定 | **做了。** 那一行展开成通知页同一张卡（`Inbox.tsx` 的 `Detail`）：每一步、草稿全文、接受 / 改一下 / 不用了、回答任务的提问。T4 要加的（理由放最前、键盘、撤销、10 秒后才发出）还没有 |
| 没钟点的待办有建议的钟点（虚线） | **做了，按规则，不用模型。** 从现在起今天第一个空着的半小时，9 点到 21 点之间，最多 3 条，其余留在「今天之内」；晚上转向明天之后不建议。点「放进日历」在日历上建一个 30 分钟的同名日程；没有可写的日历就只显示建议，没有按钮 |
| 学习的那一行 | **做了最薄的一版。** 「学习」领域的待办标一句「学习」；链接页里归在学习主题下、还没看过的链接，最多 2 条，排在「今天之内」。没有进度：Learning Hub 还在 Robin 里。学习安排写在日历里的（日程没有领域）不会被认出来 |
| 「可能要回」的信和理由 | 今天未读、Gmail 标了重要、是人写的信，最多 3 封，没有理由。早报已可关联引用的邮件；「今天」还没有接入这些引用 |
| 页尾「07:30 写的 · 更新」 | 没有，跟着上一条 |

顺带的一条规则：一条没钟点的待办，和今天还没开始的一个日程同名，就是同一件事，只画一行（待办的圆圈，日程的钟点和入口）。「放进日历」之后靠它不出现两行，你自己在日历里给待办排了时间也一样。

另外多做了一条原型里没有的：等你的事里，标题和说明一模一样的只显示一行（同一提议的几个版本）。通知页里它们仍然各占一行，那要等 T4 合并。

### 3.1c 排一下今天（2026-11-22，原型做了，等你看）

你说「今天」不能只是看，要能排。原型：[prototype/plan.html](../../prototype/plan.html)。图标你已经自己改成了小房子（`shell/icons.tsx` 的 `home`），上面 3.1b 说的超立方体作废。

**一次排整天，画在原来那条线上，不另开一页。**

| | 怎么做 |
| --- | --- |
| 谁排 | Alfred 一次排整天：先后、每件要多久（猜一个，显示出来）、放哪个空档、放不下的挪到明天，每件一句理由。行的样子和 3.1b 一样，钟点画虚线 |
| 怎么改 | 点一行，在原地改：换一个空档（只给放得下的）、改长短、挪到明天、不定钟点。改了别的自己重新排开 |
| 怎么定 | 整个计划一个「就这样」。待办拿到钟点（`at`），**日历不动**；某一件要进日历，打开那一行点「放进日历」 |
| 什么时候排 | 早上和早报一起排好，打开 App 时等你点头；没开早报的，「今天之内」那条线上有「排一下」 |
| 落后了 | 过了钟点还没勾的，从现在往后重排，原来的钟点划掉；「就这样」或「我自己来」（保持原样） |
| 收尾 | 晚上：「今天还有 N 件没勾，挪到明天？」一下全挪，或一件一件选（明天 / 做完了 / 不要了） |

**分工：模型判断一次，规则摆位置。** 模型给先后、长短、哪件今天不放和理由；往空档里摆用规则（和现在建议钟点的规则同一条）：09:00–18:30，午饭 12–13 留着，每个会后、每件后留 5 分钟，离现在至少 5 分钟，按 Alfred 的先后放进第一个放得下的空档。规则摆不下的挪到明天，理由是「今天排满了」或「要 2 小时，今天剩下最长的空档 1.5 小时」。

**和「只告诉，不替你准备」不冲突**：那条说的是往外发的东西（回信草稿）。计划只动你自己的待办，点头之前什么都不生效。

**还没定的**【默认】：

1. 一天从几点排到几点、午饭几点：先写死 09:00–18:30 和 12–13，以后放进设置。
2. 钟点写在待办上，不写日历；要不要有个开关「计划一律进日历」。
3. 落后了要不要自己弹出来：原型里是你打开「今天」时才看到，不推通知。
4. 每件要多久：模型猜；你改过的长短记下来，下次同类的照着猜。

### 3.2 两层：事实和判断

| 层 | 内容 | 什么时候更新 | 要不要模型 |
| --- | --- | --- | --- |
| 事实 | 下一件、倒计时、日程、待办、邮件数、在办、刚办完、等你 | 实时，跟着主节点的状态 | 不要 |
| 判断 | 哪几封可能要回和理由、建议先做哪件、待办的建议时间、学什么 | 每天早上写一次；页面上有「更新」【已定】 | 要，一次 |

判断层写着「07:30 写的」。事实变了而判断没变时（一封「可能要回」的信你已经回了），那一行自己划掉，不等重写。

**现在的「早报」变成这一页的判断层。**【事实】早报是一条模板自动任务（`brief`，默认关），每天跑一次，结果作为一条通知送进通知页；每期可查看「这一期实际读了哪些日历、待办、邮件」（`MorningBriefEvidence`）。改法：同一条自动任务，产出从一段话改成结构化的几项判断，落在「今天」上；来源记录原样用来写「读了日历、待办、12 封邮件」。往期仍在自动任务页按日期查。它不再是通知页里的一条。

## 4. 通知

### 4.1 放什么

**放**（都是 Alfred 自己的事在等你）：
- 任务的提问、要权限；
- 被打断的任务，要不要接着办；
- 你让 Alfred 准备的改动（提议）：一封你要它写的回信、一次你要它做的清理；
- 对外的改动失败了，或不确定成没成；
- 登录过期、自动任务连续失败这类「Alfred 办不下去了」。

**不放**：
- 邮件要回、截止日、日程冲突：归「今天」。
- 建议的待办：留在待办页，「今天」提一句，不算进通知的数字。【已定】
- 你要的报告和清单：在「今天」的「刚办完」里读。【已定】
- 办完的会话：「今天」的「刚办完」。【已定】

通知页的数字（侧栏、手机底栏上的那个）只数「放」的那几类。

**提问应该很少。** 你 2026-11-20 说过：「问我这么多次不如我自己加了。」Alfred 先按最可能的意思办，让提议或容易改的结果来接住修正；通知里出现一条提问，说明它真的办不下去了。通知页越短越好：它量的是 Alfred 还有多少事离不开你。

### 4.2 告知类：看过自己消失

「已发送」「办好了」「你不在时」这类只是告诉你的，**仍进通知页，排在等你的下面，没有「知道了」按钮**。【已定】

「看过」的定义【默认】：它在你正看着的通知页上显示过，你离开这页时它才走，进记录。不会在眼前突然消失。

### 4.3 一张卡

- **保留现在提议卡里的东西**【事实：现在就有】：逐条列出要做的事、草稿全文、「只执行这些，不多做」、有效期、东西变了就作废。
- **加**【已定】：
  - 一句 Alfred 为什么这么建议；第一个按钮就是它的建议。
  - 键盘：↵ 照办，E 改（挂到底下那一行），X 不，J/K 换一件，Z 撤销。
  - 撤销代替确认。要发出去的（邮件、通知别人的日程改动）在「发送」后 10 秒才真的出去，这 10 秒可以撤销。
- **一栏，不分左右**。每张卡在列表里就能决定，不用点开。
- **卡住任务的排最前**，写着卡了多久。

### 4.4 同类合并

同一件事的多个版本只留最新的一张。【事实：演示里同一封回信的三个提议各占一行】同一类的几件（三封你让它写的回信）合成一张，可以一起办，也可以逐件看。【已定】

### 4.5 记录

通知页最下面折着「记录」：谁决定的、什么时候、在哪台设备上说过。【事实】`notice.assigned`、`notice.presented`、`notice.acknowledged` 这些事件已经在记，只是没有界面。

### 4.6 不说两遍

你正看着通知页时，列表里已有的条目不再弹说话的卡片。【默认】怎么分派不变（[attention.md](attention.md)），只是窗口在通知页上时不为列表里看得见的条目出卡。

## 5. 邮件和通知

- **邮件页是信本身。** 未读邮件从来不是一条通知。
- **Alfred 读信，不替你回。** 它在「今天」里说「这封可能要回」和一句理由。【已定】你的原话：「不一定要直接写好 draft 回 email，就是跟我说这个可能要回就行。」
- **你开口了才起草。** 在那封信下点「起草回复」或在底下那一行说一句，草稿写在信下面（现在就是这样）。因为是你让它写的，这份草稿算一件「等你」，通知页数得到。
- 现在的代码里也没有自动起草【事实】；这一条是把它定成规矩，以后加功能时不越过。

## 6. 首次引导

**什么时候**：全新的 Alfred 第一次打开时，全屏。【已定】这次改版上线后，已经在用的人也看到一次，跳过已经设好的步骤（对你来说只剩「早上几点」和「走一圈」）。【已定】设置 → 通用里可以再看一遍。

**步骤**【已定】，每一步都能跳过，之后在设置里补：

| # | 步骤 | 说明 |
| --- | --- | --- |
| 1 | 名字 | 形象从一个点长出来，问「我应该如何称呼你？」。这一问原来在通知页前面，已经挪到这里（2026-11-20） |
| 2 | 接上模型 | 登录订阅或填密钥。唯一不建议跳过的一步 |
| 3 | 接上 Google | 日历和邮件。接上了「今天」才有东西可写 |
| 4 | 早上几点写「今天」 | 开不开每天那一次判断，几点 |
| 5 | 走一圈 | 进到真实界面，其余变暗，形象走到每一处说一句，三四站，随时可跳过 |

**走一圈的几站**【默认】：「今天」（我每天早上在这里写给你）→ 通知（我卡住的事在这里等你）→ 底下那一行（交代我做事、问我、搜索）→ 侧栏（别的页面）。落在「今天」。

**通知页前面的两样东西都去掉**【已定】：问名字（挪到第 1 步）和每次进门的 5 秒问候。通知页空的时候只有一行「没有事在等你」。

**问候改成全局的，打开 App 时出现一次**【已定，2026-11-20 晚，改了当天早些时候的第 16 条】：不管落在哪一页，页面在后面模糊（和日历上弹卡片时一样的做法），中间是形象和一行「{名字}，欢迎回来。」。形象用 3.3 秒展开，再停留 4 秒后淡出。开启「减少动态效果」时直接展示完整形象 4 秒。点按画面任意位置或按任意键可立即进入。「今天」第一行的问候照旧。**已做**（`shell/Welcome.tsx`）：
- 从通知点进来（链接里带着具体哪一条）时不出现，直接到那一条。
- 问候上方显示设备的本地时间、日期和星期。底部的小字淡入，提示可以点击或轻触任意位置返回工作区。开启「减少动态效果」时，小字直接显示。
- 只对打开时就有名字的人出现。「{名字}，很高兴认识你。」是首次引导里答完名字那一下说的；之后在设置里补填名字不再弹。
- 它在的时候，别的通知先不弹。久别回来由形象说的欢迎语（带「办完了几件」）是注意力那一层的事，不变。
- 没有卡片托着字，所以背后比日历那种更糊一些（16px、盖 66% 的页面色），不然字会和背后的页面搅在一起。
- 通知页前面的 5 秒问候和问名字都已经拿掉：通知页打开就是列表，空的时候只有「没有事在等你」。

## 7. 搭建顺序

每一步都能单独用。先做「今天」的骨架，因为它不要模型，当天就能看到东西。

| 步 | 内容 | 验收 |
| --- | --- | --- |
| T0 原型 **（已做，2026-11-20，等你看）** | `prototype/today.html`：「今天」、收窄后的通知、从「今天」打开一封信再让 Alfred 起草、首次引导的五步和老用户看到的那一次。顶上的条切页面、早中晚三个场景、中英文、深浅。`prototype/inbox.html` 是对齐之前做的（把在办和结果放在通知页里，还有自动写好的回信草稿），已经被它取代 | 你看过、点头 |
| T1 「今天」骨架 **（已做，2026-11-20，等你看）** | 新页面 `core.today`，排在第一个（默认页就是 `pages[0]`，`App.tsx`）。只有事实层：第一行、下一件、今天的时间线、邮件数、在办、刚办完、等你的前几件 | 不开模型也有内容；每一行点得进去；320px 中英文不叠字 |
| T2 通知收窄 | 第 4.1 节的界线；结果和会话完成移到「今天」；告知类看过自己走；去掉进门的问名字和问候；一栏；同一提议只留最新；通知页上不重复弹卡 | 数字只数等你的；没有「知道了」；打开就是内容 |
| T3 判断层 | 早报自动任务改成给「今天」写判断：可能要回的信、先做哪件、建议时间、学什么；「更新」按钮；写着几点写的 | 关掉它，「今天」仍然完整，只是少这几行 |
| T4 通知的卡 | 理由和建议、键盘、撤销和 10 秒后发出、同类合并、记录 | 四件事不用鼠标 10 秒内处理完；发出去之前撤得回来 |
| T5 首次引导 **（已做，2026-11-20，等你看）** | 全屏五步；老用户看一次；设置里可重看 | 全新的数据目录走完落在「今天」；每步可跳过 |

**T1 做了什么**：

- 读模型在 `packages/ui/src/shell/today.ts`（`todayModel`，纯函数，不存东西、不调模型），测试在 `packages/ui/test/today.test.ts`。页面是 `Today.tsx` 和 `today.css`。
- 排在页面表的第一个，所以打开 Alfred 落在这里；侧栏和手机底栏的第一个图标是它（形象的六边形，Alfred 色）。
- 有的段：第一行（问候 + 正在进行的或下一件，带「进会议」或「在日历里打开」）、等你的前 3 件、今天的时间线（日程和有钟点的待办，带「现在」那条线）、今天要做但没钟点的、逾期条数、邮件（今天几封、未读的几封）、在办和下一次自动任务、刚办完。
- 每一行都点得进去：等你的进通知页那一条，邮件进邮件页的**那封信**（页面之间多了一条路：`go(页, 东西)`；邮件页认 `#p=mail.inbox&item=<账户>|<id>`），在办和刚办完进那条对话或会话，其余进各自的页面。
- 和第 3 节的出入，留给后面几步：
  - 「等你」现在是三行入口，点进通知页决定；当场决定要等 T4 的卡做出来再搬过来。
  - 「刚办完」只列**没看过的**（没读的回复、你说过做完告诉你的结果）；「看过的变淡、留到当天结束」没做，因为现在没有地方记「今天看过哪些」。
  - 会话的「有改动没提交」没标：状态里没有这个数。
  - 待办在这页不能直接打勾，点了进待办页。
  - 没有学习段（T6）和页尾的「几点写的 · 更新」（T3）。
- 只在英文界面的演示数据上实际看过（桌面宽和 375px，没有叠字）；中文界面没有在 App 里看过，文案和原型里的一样。
- 你在真数据上看过之后（2026-11-20 晚）修了两处：日程的地点是一个网址时，变成一个写着站名的入口（原来是一行不能点的字）；邮件摘要里的 `&#39;` 这类转义读出来时还原成字。
- 同一晚又改了三处（你说「123 都改了」）：
  - **晚上转向明天。** 18 点以后，今天带钟点的事都过去了（没有正在进行的、没有下一件、也没有还没到点的待办），这页就讲明天：第一行说明天第一件，下面依次是「今天还没做完」（今天还开着的待办和逾期条数）、「明天」的时间线、一行折起来的「今天的 N 件日程」。有一条今晚 22:00 截止的待办时不转，仍然讲今天。
  - **有信息的那半句用墨色。** 「今天没有别的安排了」不再加粗，加粗的是「明天第一件是…」。顶栏那一句改成按数报（「今天 3 件日程 · 1 条待办 · 4 件等你」），不再重复页面的第一句。
  - **机器发的信只报数，不列出来。** 验证码、登录和安全提醒、no-reply 发件人，按发件地址和开头几个字的固定规则认（`machineMail`，不是判断好坏），在邮件那段末尾合成一行「另有 N 封验证码、登录提醒」，点了进邮件页。列出来的只有人写的未读信。

**T5 做了什么**：

- 组件在 `packages/ui/src/shell/FirstRun.tsx`（样式 `first-run.css`）；哪几步还欠着是纯函数 `shell/first-run.ts`，测试在 `packages/ui/test/first-run.test.ts`。
- 走没走过记在主节点：设置里多一项 `firstRunAt`（走完或跳过的时间）。是空的，下一台打开的设备就出引导；所以每个人只看一次，不分设备。从通知链接点进来的那一次不出，留到下次。
- 已经设好的步骤不出现：有名字不问名字，接了模型不出模型那步，接了 Google 不出 Google 那步，早报已经开着不问几点。老用户因此只看到没设过的和「走一圈」。
- 模型和 Google 两步用的就是设置页的那两块（`ModelSettings`、`Accounts` 加了 `setup` 模式，只留「怎么接上」），登录流程没有另写一份。
- 在不存凭证的设备上（手机）读不到这两项，这两步不出现。这台 Alfred 没有 Google 客户端时，Google 那步不出现。
- 跳过模型那步，「早上几点」也不问：没有模型，开了每天都会失败。
- 走一圈四站：「今天」第一行 → 通知（侧栏里那一项；手机是底栏的图标）→ 底下那一行（手机是右下的 Alfred）→ 侧栏（手机是底栏）。侧栏收着的会先打开，走完恢复原样。← → 换站，Esc 结束。
- 设置 → 通用里有「首次引导 · 再看一遍」，只在这台设备上重放。
- 和第 6 节的出入：
  - 第 4 步的标题现在写的是「每天早上几点写**早报**？」，因为 T3 没做，那一次判断现在还是早报、落在通知页；T3 做完改回「写『今天』」。
  - 老用户那一步没有「这次更新多了『今天』这一页」那句专门的话。
  - 形象「从一个点长出来」只在它是页面上第一个形象时发生（现在的 `Figure` 就是这样），引导打开时底下已经有一个，所以多数时候是直接出现。
- 实际看过：全新数据目录，英文和中文，桌面宽和 375px，五步加走一圈；老用户（有名字）只出剩下的几步。没试过的：真的登录一个订阅或 Google 之后「继续」按钮出现（没有在测试目录里动你的凭证）；Mac App 里的窗口。

T2 里去掉问名字不用等 T5：没有名字时问候就不带名字，现在也是这样【事实：`welcome.greeting`】。

## 8. 这一轮不做

- **晚点再说**（把一件事推到今晚或明早）：要给通知加送达时间。
- **「以后这类直接办」的规矩**：要新做一套规矩和授权。
- **Learning Hub**：整组搬迁，另有计划（`docs/SESSION-HANDOFF.md`）。
- **手机推送上直接决定**、滑动手势。
- 提前写好回信草稿，哪怕是重要的人来信。

## 10. 我的默认，等你点头

1. **「看过」的定义**（4.2）：在你看着的通知页上显示过，离开这页时才走。
2. **「今天」顶上带几件**：最多 3 件，按卡住多久排。
3. **开发会话的改动没提交**：只在「刚办完」那一行上标一句「有改动没提交」，不进通知。第 3 题的选项里我写过「等你看改动」也进通知；按第 11 条的界线，办完的会话没有卡住，所以改成这样。它要提交或开 PR 而需要你批准时，那是一个提议，进通知。
4. **「刚办完」留多久**：留到当天结束；看过的变淡。
5. **走一圈的四站**（第 6 节）。
6. **「今天」的图标和颜色**：Alfred 色，图标用形象的那个六边形；侧栏里排第一。
7. **通知页上不重复弹卡**（4.6）。
8. **建议时间怎么排**：只用今天日程之间不短于 30 分钟的空档，截止早的先排；排不下的写「今天排不下」。
