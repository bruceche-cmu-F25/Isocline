## 0. 结论

1. **只存链接不算功能。** Robin 的 Links 是"带图标、能分组的书签"。要做的是另一件事：你随手丢进来一个网址，Alfred 去读它，告诉你**它在哪、在说什么**，自己归好类，以后你用一句话就能**找回来**。
2. **两种东西，两种样子。** 「常去」是入口（Gmail、日历、GitHub），做成一排图标，不读、不总结。「收下的」是内容（一个视频、一篇帖子、一篇博客），做成卡片，要读、要总结、要分类。
3. **读得多深，照实说。** 博客读正文，YouTube 读字幕，这两种第一版就能做好。B 站和小红书有登录墙，第一版只到标题和封面；要读到正文靠另外两件事接上：把截图丢给 Alfred（多文件输入），或者让 Alfred 用你登录过的浏览器去读（开发页的浏览器）。每张卡片写明总结的依据。
4. **分类两个轴。** 类型（视频、文章、帖子、工具、仓库）从网址判断，不用模型。主题由模型分：先从你已有的主题里选，不合适才提新的；你改过的归类会带进下一次判断。
5. **读网页的那次调用不给任何工具。** 网页是别人写的话，可能夹带指令；没有工具，它就什么也做不了。
6. **页面三段：** 常去、刚收的、按主题分区。【已定，2026-11-19】不做二维的地图，只做分区。

## 1. 现在到哪了

【事实】

- Alfred 里没有 Links。Robin 里有：一条链接是 `{ id, title, url, group?, icon?, createdAt }`；保存时抓页面的 `<title>` 和图标；分组是用户自己写的名字，再按关键词表归成六个"家族"（求职、灵感、学习、财务、项目、日常）；模型有 `link_add`、`link_list` 两个工具。没有正文、没有总结、没有搜索。
- Robin 另有一个独立的"视频摘要"工具：只收 YouTube 链接，读公开字幕，出中英双语的总结和带时间戳的要点，并写明"来源是字幕，没有分析画面"。它和 Links 没有连在一起。
- Alfred 的地基够用：模块契约（操作、工具、快照）、无人值守的任务、提议、"建议的待办"（虚线行，点了才算）。
- 这台机器上有 `ffmpeg`，没有 `yt-dlp`。主节点上有本地的语音转写（Qwen3-ASR 0.6B），现在只给听写用。
- Pi 的 `prompt` 只收文字和图片。

## 2. 从第一性原理出发

你收一个链接，不是为了"拥有"它，而是下面三件事之一：

| 你想的是 | 以后要的是 | 所以需要 |
|---|---|---|
| 这个地方我老去 | 一下就到 | 入口，在手边 |
| 这个我想看 / 想读，现在没空 | 记得有这回事，知道值不值得花时间 | 它在说什么，多长 |
| 这个以后可能有用 / 我想照着做 | 需要的时候找得到 | 按内容能搜到；能变成一件要做的事 |

书签只解决第一件。后两件的共同点是：**你不会记得标题，只记得大概在说什么。** 所以每条收下的东西都要有 Alfred 读出来的内容，搜索搜的是内容，不是标题。

## 3. 通用语言

| 词 | 含义 | 不是 |
|---|---|---|
| 常去（place） | 一个你反复去的地址，钉在页面顶上 | 不读、不总结、不分主题 |
| 收下的（clip） | 一条你存下来的内容：一个视频、一篇文章、一条帖子 | 不是书签；它有读出来的内容 |
| 读（reading） | Alfred 取回它能取到的原文，并写出总结 | 不是"看过"；你看没看是另一回事 |
| 依据（basis） | 总结是根据什么写的：正文 / 字幕 / 转写 / 截图 / 只有标题 | 不是可信度打分 |
| 类型（kind） | 视频、文章、帖子、工具、仓库、文档 | 从网址和页面信息来，不问模型 |
| 主题（topic） | 它在讲什么的那个圈子，例如"RAG""租房""咖啡" | 不是领域；一个主题挂在一个领域下 |
| 领域（area） | 核心里已有的七个：工作、生活、学习、出行、健康、财务、家人朋友 | 不新增 |
| 念头（note） | 你收下时说的那句话："想周末试试" | 不是总结 |

## 4. 方案

### 4.1 一条收下的东西长什么样

【建议】一张卡片回答四个问题，按这个顺序读：

1. **在说什么**：一句话（不超过 40 个字 / 25 个词）。展开后是 3–6 条要点；视频的要点带时间戳，点了从那一秒打开。
2. **在哪**：平台图标、作者或站点、时长或阅读分钟数、封面（有就用）。
3. **为什么收**：你的念头，原话。
4. **算哪类**：类型标记 + 主题（带领域的颜色）。

卡片底部一行小字是依据："根据字幕""根据正文""只读到标题"。只读到标题的卡片不装作有总结，那一行直接说"还没读到内容"，并给出能补上的办法（丢一张截图 / 贴一段文字）。

状态只有三个，都是你的事：**没看**、**看过**、**想做**。"想做"会在待办页出现一条建议的待办，挂着这条链接（已有的机制）。

### 4.2 一条链接的一生

```text
收下（任何入口）
  → 立刻：整理网址、去掉跟踪参数、查重；占一张卡片，状态"读取中"        （同步，不联网也成）
  → 取页面信息：标题、站点、作者、封面、时长                              （几秒，不用模型）
  → 取原文：按平台走对应的读法（4.3）                                    （几秒到一分钟）
  → 读：一次模型调用，出总结、要点、主题、要不要建议一条待办              （后台模型，无工具）
  → 落地：卡片填满；主题是新的就在卡片上标"新主题"，你可以改
```

每一步的结果都存下来，失败停在那一步并在卡片上说明（"这个页面要登录""没有字幕"），不会静默地变成一张空卡片。可以重读。

【建议】读的那一步是一个无人值守的任务，用一个新的任务档 `reader`：**没有任何工具**，输入是取回的原文（有长度上限），输出是固定结构（JSON）。它不能改世界，结果由链接模块自己写入。这样既不用担心网页里的指令，也不会把一次总结变成一段对话。

### 4.3 读得多深

【事实 + 建议】

| 来源 | 能取到什么 | 第一版 | 以后 |
|---|---|---|---|
| 博客、新闻、文档 | 正文（去掉导航和广告） | 读正文 | |
| YouTube | 公开字幕（含自动字幕）和时间戳；标题和频道走 oEmbed（它的播放页把标题埋在几兆脚本后面） | L1 取标题和频道；L2 读字幕，要点带时间戳 | 没字幕的转写音频 |
| GitHub 仓库 | README、描述、星数、语言 | 读 README | |
| PDF 链接、arXiv | 文字 | 读前若干页 | |
| Bilibili | 【事实，2026-11-19 实测】视频页和它的公开接口都只回答浏览器：Alfred 照实报出自己是谁（`Alfred link reader`），页面给的是空壳，接口回 412 | 只有从网址得来的名字（`bilibili.com · BV…`），卡片标"没取到标题"；你可以自己改标题 | 内置浏览器；转写音频 |
| 小红书 | 【事实，实测】笔记页直接跳到登录页；分享文字里有标题 | 认出登录墙，卡片标"要登录才看得到"；从 App 里分享过来的那行字会留作念头 | 截图；内置浏览器 |
| 微信公众号 | 正文多数能直接取到 | 读正文 | |
| X、微博等 | 多数要登录 | 只到标题 | 截图；内置浏览器 |

读不到正文的三条补法，都依赖别的功能，所以排在后面：

- **截图**：你把截图拖进输入框，说"这是那篇小红书"。视觉模型读图，依据记为"截图"。依赖多文件输入（另有文档）。
- **内置浏览器**：Alfred 在 Mac App 里用你登录过的浏览器页打开它，读页面文字。依赖开发页的浏览器（另有文档）。只在你点了"用浏览器读"之后做，不自动。
- **转写**：下载音轨，用主节点上已有的本地转写。要装 `yt-dlp`；一个 20 分钟的视频大约要转一两分钟；各站的条款不一样，所以默认关，按次点。

### 4.4 分类

【建议】

- **类型**：一张规则表（域名和路径 → 类型和平台），加页面的 `og:type`。确定性的，可测。
- **主题**：模型在"读"那一步一起给。提示里带上你现有的主题清单（名字、挂在哪个领域、各有几条）和最近你**手动改过**的几条归类。规则：
  - 先从现有主题里选；只有都不合适才提新主题，而且新主题要给出挂在哪个领域。
  - 一条只属于一个主题（在页面上只出现一次）；另给最多三个关键词，只用于搜索。
  - 同一个主题少于 2 条时，在分区视图里归到"零散"，不单独占一块，免得满屏都是只有一张卡片的分区。
- **你的修正是规则**：把卡片拖到另一个主题、给主题改名、合并两个主题，都是点一下的事。改名和合并对已有的卡片立即生效；以后的归类会看到这些修正。
- 不做多级主题树。两层（领域 → 主题）够用，也画得下。

### 4.5 界面

【建议】一个新页面「链接」，在日常那一组里。见 `prototype/links.html`。

**顶上：常去。** 一排图标加名字，一行放不下就横向滚。最右是"+"。它们也出现在 ⌘K 里。

【已定】常去是你自己的：一开始只放几个最平常的（Google、Gmail、YouTube），都可以删、改名、换顺序。（Google 日历原来也在默认里，它拿不到图标，Bruce 2026-11-19 说去掉。）其余的由你加（点"+"贴一个网址），或者让 Alfred 加（"把 Canvas 钉到常去"，工具 `link_pin`）。不从浏览历史里学，也不默认从 Robin 导入。

【已实现，2026-11-21】点「编辑」可以整理常去。把两个网站叠在一起建文件夹，拖到图标之间排序。文件夹用前九个网站预览，可以改名。打开文件夹后，可以把网站拖回顶层，也可以选中后点「移回常去」。最后一个网站移出时，空文件夹消失。⌘K 可以按文件夹名、网站名或网址找回它们。

**中间：刚收的。** 最近收下、你还没看的，最多五条，新的在上。正在读的卡片有读取状态。这一段空了就不显示。

【已实现，2026-11-21】视频卡片使用网站提供、由主节点缓存的横向封面。筛选结果里有两条或更多待看视频时，它们集中到「待看」架，在页面上只出现一次。

**下面：按主题分区。** 每个主题一块，标题是主题名、领域的颜色点、条数；里面是卡片。主题按领域排，同一领域的挨着。手机上是一列。条目多了不乱，能扫读。

【已定】v0.1 还提过另一种做法：一张二维的地图（领域是区域，主题是一团，每条是一个点）。Bruce 看过原型后定了不要，先只做分区。

**页面底部的那一行**（已有的 ask bar）就是入口：贴一个网址进去，它上方显示"收进链接"，回车就收；后面跟一句话就是念头。问"上周那个讲 RAG 的视频"也在这里问。

**筛选**：一行小标签，类型（视频 / 文章 / …）和状态（没看 / 想做）。不做复杂的筛选面板。

### 4.6 怎么收进来

【建议】按做的先后：

1. 页面底部那一行贴网址（上面说了）。
2. 对 Alfred 说或打字："把这个存一下 https://…，周末想试试"（工具 `link_save`）。
3. 手机：把 Alfred 的 PWA 注册成系统"分享到"的目标（Web Share Target），在小红书、B 站、YouTube 里点分享 → Alfred。**这是手机上最要紧的入口**，因为那些内容你是在手机上刷到的。iOS 的 PWA 目前不支持 Share Target，所以 iPhone 上先用一个"快捷指令"把分享的网址发给主节点（一次配置）；这一条要实测。
4. 把网址拖进窗口。
5. 以后：内置浏览器里的"收下这一页"；邮件、待办里出现的链接旁边一个小按钮。

### 4.7 找回来

【建议】

- 工具 `link_search`（读）：按内容搜，搜的是标题、总结、要点、关键词、你的念头，以及存下来的原文摘录。先用 SQLite 的全文索引（FTS5），不上向量库；不够用再说。
- 工具 `link_save`（本地，可逆）、`link_list`（读）、`link_update`（改主题、状态、念头）。删除按"永久删除每次问"的老规矩。
- Alfred 在别的对话里也能用到它们："帮我规划周末" → 它能看到你标了"想做"的那几条。
- 早报里可以带一行"收了 3 条还没看"（一个数，不是清单）。

### 4.8 数据

【建议】模块 `links`，表：

- `links_items`：`id`、`url`（整理后的）、`kind`（place / clip）、`type`、`platform`、`title`、`author`、`cover`（本地缓存的文件名）、`duration`、`note`、`topic_id`、`state`（unread / seen / todo）、`pinned`、`position`、`saved_at`、`read_state`（pending / reading / read / partial / failed）、`read_error`。
- `links_readings`：`item_id`、`basis`、`tldr`（按语言）、`points`（JSON：`[{ at?, text }]`）、`keywords`、`model`、`read_at`、`excerpt`（原文摘录，有上限，供搜索）。原文全文不长期保存：读完留摘录。
- `links_topics`：`id`、`name`、`area`、`created_by`（user / alfred）、`merged_into`。
- `links_fixes`：你改过的归类（从哪个主题到哪个），给下一次判断当例子，只留最近 30 条。
- `links_fts`：全文索引。

事件：`link.saved`、`link.read`、`link.read_failed`、`link.moved`、`link.state_set`、`link.removed`、`topic.renamed`、`topic.merged`。

从 Robin 导入：不是默认行为（第 8 节第 4 条）。以后可以加一个明确的命令，只读地把 Robin 的链接读进来作为「常去」；L1 不做。

### 4.9 取网页这件事

【建议】一个共用的"取公开网页"的函数（Robin 的 `fetch-public-web.ts` 是现成的起点），规则写死：

- 只取 `http` / `https`；解析后的地址不能是本机、内网或链路本地地址（防止把主节点当跳板去打内网）；跟随跳转时每一跳都重新检查。
- 限时间、限字节、限类型；只发一个普通的 User-Agent，不带任何 cookie 和你的身份。
- 封面和图标下载到数据目录里再显示，页面不直接向第三方发请求（主节点的 CSP 本来也不允许）。

## 5. 安全和隐私

- **网页是别人写的话。** 读它的那次调用没有工具，输出是固定结构，写入由模块做；模型的输出里出现的网址不会被自动打开。
- **取网页会暴露"你在看什么"给那个网站**（你的 IP 和时间），和你自己点开它一样。不带 cookie。设置里写明。
- **原文会发给你选的模型。** 和邮件、日历一样的提示。读取用的后台模型可以单独选（包括本地模型）。
- **登录后的内容**只在你明确点了"用浏览器读"时读，用的是 Mac App 里那个浏览器的登录状态，不碰你的 Chrome。【有一份提案要改这条，待批准：[browser.md](browser.md)，改成用你登录过的 Chrome，只去许可的站，只读】
- **花费**：每条一次模型调用。设每日上限（第 8 节），超过的排到第二天，卡片上写"排队中"。
- 配对的设备能看、能收、能改归类；取网页和读都发生在主节点上。

## 6. 搭建顺序

每一刀都能单独用。

1. **L1 模块和页面**【已实现，2026-11-19】：表、操作、常去（默认几个，可增删改）、收下时取标题 / 站点 / 简介、类型规则、分区视图、你手动归主题、Alfred 的 `link_save` / `link_pin` / `link_list` / `link_update` / `link_remove`（经 Alfred 收的，它当场就能归主题）。封面图先不下载，用类型图形。到这一步它还不会读正文。
   - **站点图标**【Bruce 2026-11-19 要的】：用网站自己的图标（favicon）。主节点每个站点取一次（页面里写的 `apple-touch-icon` / `icon`，没有就 `/favicon.ico`），按字节认出是不是图片（PNG、JPEG、GIF、WebP、ICO、SVG，300KB 以内），存在库里的 `link_icons`（迁移 `link:2`），由主节点自己提供：`GET /api/modules/link/files/<host>`（module-kit 新加的 `file`，只发图片，带 `nosniff` 和一个什么都不许加载的 CSP）。界面从不直接向那些网站要图。没有图标的站点一周后再问一次，这期间用字母块。图标不进仓库。实测：Google、Gmail、YouTube、GitHub、小红书、B 站都取到了。Google 日历取不到：它的页面没登录就跳到 Google 的登录页，所以读不到页面里写的图标地址；而它的 `/favicon.ico` 转到 `/calendar/favicon.ico`，那里是 404。它因此不在默认的常去里；你自己加上的话显示字母"GC"。
