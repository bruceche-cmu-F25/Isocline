## 1. 结论先说

- **领域**：从代码里的七个常量，变成用户自己的一张表。七个照旧在，只是首次运行时写进去的样例，能改名、换色、排序、删除，也能新建。
- **早报**：**继续是一个自动任务**，作为 App 自带的样例（默认关着）。代码里所有"这是不是早报"的判断都拆掉，换成**每个自动任务都能用的选项**。这样用户能改早报，也能照着它做"周报""晚间回顾"，样子和早报一样。
- **「今天」不依赖早报。** 「今天」页直接读日历、待办、邮件、通知这些事实，不调模型、不读早报（`shell/today.ts` 的开头写着）。早报是模型写的一期稿，发到通知页，形象会念出来。两者内容有重叠，但谁也不靠谁；关掉或删掉早报，「今天」照常。
- **Robin 导入**：整个删掉。

## 2. 领域

### 2.1 现在

`packages/core/src/areas.ts` 里一张冻结的常量表：七个领域（工作、生活、学习、出行、健康、财务、家人朋友），每个带中英文名和一个颜色槽。待办和链接的主题按这张表校验，Alfred 的工具说明也是从它拼出来的。另外「今天」页单独认了 `learn` 这个 id（`shell/today.ts:101`），给学习类的待办加"学习"字样。

### 2.2 改成

**数据**：主节点一张表 `core_areas`：id、名字、颜色槽、顺序、来源。

- 七个样例首次运行写入，id 不变（`work`、`life`……），已有的待办和主题不用迁移。
- 样例在用户改名之前，名字跟着界面语言走（和自动任务样例现在的做法一样：名字存空，显示时取翻译）；用户一改名，就用他的名字。
- 删掉的样例不会再写回来（同样照自动任务样例：看事件记录里有没有建过）。
- 新建的领域 id 用随机 id，名字就是用户写的那个。

**颜色**：从现有七个颜色槽（蓝、绿、紫、橙、青、黄、粉）里选，外加灰色。新建时自动给用得最少的那个，用户可以换。领域可以多于七个，颜色可以重复。不加新颜色槽：七个的顺序是按色盲区分度挑过的。

**删除**：卡片里写明"有 N 条待办、M 个主题在这个领域"，默认它们变成"不归任何领域"，也可以选"移到另一个领域"。

**校验**：`isArea(id)` 改成查表（要传 world）。Alfred 的工具说明不再在启动时拼死，改为每次运行时把当前的领域列表放进说明。

**「今天」页的 `learn` 特判删掉**：每条待办显示它自己领域的名字，不再给某一个领域单独的字样。学习模式以后有自己的「课题」，不靠领域 id。

### 2.3 在哪设置

【已定】（2026-11-22）**只放在设置里。**

- **设置 → 通用**：一节"领域"，一行一个领域，名字可直接改，左边是颜色点（点开选色），能上下移动排序，右边删除；底下一行"新建领域"。
- 待办页和选领域的地方只用领域，不管理。
- **让 Alfred 建**：一个 `area_add` 工具。用户说"加一个'孩子'领域"就直接建（建领域容易撤回，按 Alfred 先猜再做的规矩，不先问）。改名和删除只在用户明说时做。

### 2.4 用户能自己建什么、改什么

新建、改名、换色、排序、删除领域；样例和自己建的完全一样对待。

## 3. 早报

### 3.1 现在代码里认"早报"的地方

| 地方 | 做的事 |
|---|---|
| `briefEditorial.ts`、`MorningBrief.tsx` | 按固定的中英文小标题（日程、到期事项、邮件与决定、建议先做）把结果拆成几块，画成一页 |
| `server/morning-brief.ts`、`brief-sources.ts`、`/api/runs/:id/morning-brief` | 从这一期的运行记录里读出它查过哪些日程、待办、邮件，作为"依据" |
| `core/result-delivery.ts`、`runs.ts:326` | 通知页里只留最新一期 |
| `core/conversations.ts:76` | 早报的对话在用户开口前不出现在对话列表 |
| `shell/FirstRun.tsx`、`first-run.ts` | 首次引导问要不要开早报、几点 |
| `shell/pages.tsx:242` | 有早报时多一句建议问法 |
| `Automations.tsx:116` | 按模板给颜色 |
| `schema.ts:253` | 数据库只认 `brief`、`mail_todos` 两个模板 |

样例本身的机制已经是对的：首次运行建好、默认关着、用户删了不再建、名字和要求跟着语言走（`automations.ts` 的 `ensureTemplates`）。要改的只是上面这张表。

### 3.2 怎么办：三种做法比较

1. **系统自带的功能**（早报不再是自动任务，而是「今天」或通知页的一部分）。不选：用户改不了它怎么写，也做不出第二份。
2. **一直自动**（不让关）。不选：不是每个人都要早报；而且还是一份写死的东西。
3. **【建议】仍是自动任务，自带一份当样例，所有特殊之处变成自动任务的选项。** 下面按这种写。

### 3.3 改成

**模板 → 来源。** `template` 列改名为 `origin`（例如 `sample:brief`），去掉只认两个值的限制。它只剩两个用处：没改过时名字和要求跟着语言走；删了不再建。**再没有任何行为按它判断。**

**每个自动任务都有的选项**（自动任务编辑卡片里加"更多"一栏，样例预先填好）：

| 选项 | 取值 | 早报样例的默认 | 替掉的特判 |
|---|---|---|---|
| 怎么显示结果 | 普通文字 / 分块 | 分块 | `briefEditorial`、`MorningBrief` 只给早报用 |
| 通知页里留几期 | 只留最新一期 / 都留 | 只留最新 | `retirePreviousBriefs` 只认早报 |
| 颜色 | 七个颜色槽之一 | 橙 | 按模板给颜色 |

**分块显示变成通用的。** 任何自动任务的结果，只要用 Markdown 小标题分了块，就能分块画：

- 每个小标题就是一块，标题原样显示，**不再按固定的标题名去认**。
- 每块的图标看块里的内容引用了什么：行里有 `(mail:ID)` 就用邮件图标，`(event:ID)` 用日程图标，`(todo:ID)` 用待办图标，都没有就用普通圆点。所以要先加上 `(event:ID)` 和 `(todo:ID)` 这两种写法（现在只有邮件有）。
- 行首的 `[风险] [等你] [期限 日期] [告知]` 这一套标记变成公开的结果写法，任何自动任务都能用（中英文都认），颜色照现在早报的定法（2026-11-21 选的 B）。
- 写法说明放进自动任务运行时的提示里，用户写自己的自动任务时不用记。

**依据也变成通用的。** 任何一次自动任务运行，都能看到它读了哪些东西。哪些工具算"读"，由各模块在 module-kit 里声明（现在是 `morning-brief.ts` 里写死的四个工具名）。接口改成 `/api/runs/:id/evidence`。

**对话列表**：所有自动任务的对话都在用户开口后才出现在列表里（现在只有早报这样）。不再是选项，因为没有理由让别的自动任务不一样。

**首次引导**：那一步改成"这些是 Alfred 自带的、还关着的自动任务"：每个一行，名字、时间、开关。现在两个样例（早报、从邮件挑待办）都在里面；以后加样例不用改引导。

**建议问法**：`sug.auto.brief` 换成通用的"看看{名字}"，指向最近一期有结果的自动任务。

**复制一份**：自动任务的菜单里加"复制"，方便照着早报做别的。

## 8. 其余几条（2026-11-22 第二轮）

Bruce："继续处理没有修完的其他东西，早报啦还有其他的列在交接文档里的，都修了"。按我的判断做了下面这些，没有再问。

### 8.1 早报的要点放到「今天」

- 今天跑完的、选了"分块显示"的自动任务，取最新一次结果开头的要点，在「今天」那句话下面放一行：灯泡 + 自动任务的名字 + 要点（最多三行）。点它去通知里那一期；那一期不在通知里了就去自动任务页。
- 不认早报：任何分块显示的自动任务都算。昨天的不算；结果里没有小标题（分不出要点）也不算。
- 为了读得到要点，分块显示的自动任务在状态里多留一些开头（1200 字，原来 280）。
- 你现在那一期早报是旧写法，开头就是小标题，没有要点，所以「今天」不显示；新写法的早报会有。

### 8.2 "依据"改成通用的名字

接口 `/api/runs/:id/morning-brief` 改名 `/api/runs/:id/sources`，代码里的 `MorningBriefEvidence` 改名 `RunSources`，文件改名 `run-sources.ts`、`source-reads.ts`。哪些工具算"读"、怎么读它们的结果，**仍然写在服务端**，没有挪到各模块自己声明：现在只有日历、待办、邮件三种，挪过去要让模块依赖协议包，只换了位置不换行为。等第四种能当依据的模块出现时再挪。

### 8.3 偏好（ARCHITECTURE 第 8 节的 `USER.md`）

- 做成一张表，不是一个文件：一条一句话，用户的原话。设置 → 通用 → 偏好，能加、就地改、删。
- Alfred 有两个工具：`preference_add`（用户说了一条长期的习惯或规矩，它记下来，回复里说一声）和 `preference_remove`（用户说不再这样，或叫它忘掉）。它记的那条在设置里标"Alfred 记的"；用户改过就算用户的。自动任务里这两个工具不给。
- 每次运行开头，Alfred 被告知**用户的称呼**和**全部偏好**（日常、开发会话、自动任务都是）。顺带修了一个漏洞：以前设置里的"你的称呼"从来没告诉过模型。
- 每次增改删都是事件（`preference.added/updated/removed`），谁写的、什么时候写的都查得到。最多 60 条，每条 300 字。

### 8.4 页面：用户排、用户关

- 第 3 条"模块和页面是固定清单"：ARCHITECTURE 第 8、10 节已定第一版**不做插件系统、不做模块市场**，所以用户还不能自己**加**页面或模块。这一轮做的是能做的那一半：设置 → 通用 → 页面，按侧栏的分组列出页面，每个能上移下移（在组内）、能关掉。
- 关掉的页面不在侧栏和手机底栏里，链接到它时照样能打开。「今天」、通知、开发、设置不能关。
- 存在主节点的设置里（`pages: { order, hidden }`），所有设备一样。

### 8.5 放假的词

- 原来写死的那串词（偏学生）变成样例，存在待办设置的 `offWords` 里。待办页右上"来源"里能看到全部、点 × 去掉、输入加新的；改过一次就用用户的。
- 英文词按整词（加复数）认，中文词出现就算。

### 8.6 语言

- 一个地方定每种语言的代码：核心 `LOCALE_TAGS` / `localeTag` / `acceptLanguage`，界面 `LOCALE_INFO` / `localeTag` / `nextLocale`。
- "是中文就这样、否则那样"的写法都换成按语言查表（日历、邮件模块的提示，后台推送的测试消息，修改提议的说明，权限问题）。加第三种语言时，类型检查会列出每张还缺的表。
- 修了一个真问题：开发会话里问权限的那几句（运行命令、改文件、读文件、调用工具、读浏览器页面、后台运行）以前**只有中文**，英文用户也看到中文。现在按用户的语言问：语言随每次运行传给后台进程。
- 读链接网页标题时，`Accept-Language` 跟用户的语言走（原来固定要中文）。
- Google 授权范围里那几个没人用的中文标签删了。

### 8.7 推送登记的地址

不再写在代码里。先看环境变量 `ALFRED_PUSH_SUBJECT`（用户自己的网址或 `mailto:`），没有就读仓库根 `package.json` 的 `homepage`（项目主页，别人拿去改名后改这一处）。都没有就明说要设置。不会把用户的邮箱发给推送服务。

### 8.8 还没做的

- **邮件和日历只接 Google**：在 `mail-accounts.md` 的计划里，这一轮没碰。
- **用户自己加页面或模块**：见 8.4，要先定插件的做法，现在是 ARCHITECTURE 明确不做的。
- **没用真模型跑过**：新写法的早报、Alfred 记偏好，都只在测试和演示主节点上看过。新迁移（core:30 偏好表）在你真实数据库的**副本**上跑过，没问题。
