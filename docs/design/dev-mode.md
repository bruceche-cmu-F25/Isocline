# 日常与开发：两种对话（草案）

> 状态：v0.2（2026-11-18），**已批准**：第 8 节五个决定都按建议定下。D1–D5 已做完（D5 2026-11-20）；之后是 ACP 引擎和沙箱。
> 依据：Alfred 的 `packages/engine-pi/src/worker.ts`、`packages/engine-pi/src/pool.ts`、`packages/core/src/conversations.ts`、`packages/core/src/devices.ts`、`packages/server/src/home.ts`、`packages/ui/src/Conversation.tsx`；Pi（`pi-coding-agent` 1.5.2）的 `sdk.d.ts`、`docs/security.md`、`docs/extensions.md`；Claude Code 桌面版和 pi web 的截图（Bruce 2026-11-18 给的）。
> 原型：`prototype/dev.html`。
> 标记：**【事实】** 读代码或文档核实过；**【建议】** 本方案的提案，已随批准生效；**【已定】** 第 8 节。

## 0. 结论

1. **日常和开发是两种对话，不是一个界面开关。** 差别在引擎：工作目录、能开的工具、权限、上下文、"做了什么"的证明都不一样。界面只是把这些差别画出来。
2. **新增一个核心概念「项目（Project）」**：主节点上一个登记过的文件夹。对话要么不属于任何项目（日常），要么属于一个项目（开发）。**属于哪个项目在创建时定下，之后不改。**
3. **开发对话用一个新的能力档 `developer`**，在现有的 `assistant`、`automation` 旁边。它多了 Pi 自带的读写和 shell 工具，工作目录是项目文件夹（或它的 git worktree）。
4. **开发会话有三个权限模式**：只读计划、操作前询问、本次会话始终允许。最后一项放行当前会话的项目内文件修改、shell 命令和后台命令。文件工具修改项目外的文件仍逐次询问。
5. **开发的回执是文件改动和跑过的命令。** 改动以 git 为准，不以模型的说法为准，跟"成功以回执为准"一致。
6. **界面：开发是侧栏里一个独立的整页**，按项目列出会话。日常对话照旧在右侧 Alfred 面板里。两边共用一个对话组件：顶部是标题和用量，输入框下面一条底栏放模型、思考强度、权限模式。
7. **手机能看开发会话，但要授了「开发」范围的设备才能开会话、批准命令。** 默认只有 Mac 本机有。

## 1. 现在到哪了

【事实】

- **引擎只有一种工作目录。** `pool.ts` 启动子进程时传一个 `--cwd`（数据目录下的 `engine/`），所有对话的 Pi 会话共用它（`worker.ts` 的 `open()`）。
- **引擎关掉了写和 shell。** `excludeTools: ["bash", "edit", "write", "powershell"]`，只留 `read` 给技能用；读技能目录以外的文件要先问。
- **不读项目的上下文文件。** `DefaultResourceLoader` 用了 `noContextFiles: true`，所以 AGENTS.md、CLAUDE.md 都不会进提示。
- **能力档已经是一张表。** `profiles.ts` 的 `profiles()` 返回 `assistant` 和 `automation` 两档，任务提交时带上档名。加一档不用改任务的状态机。
- **对话只有模型和思考强度两个设置**，存在 `core_conversations` 上。对话在第一次提交时隐式创建。
- **设备有类别，没有范围。** `core_devices` 记了 `desktop / phone / browser`，配对过的设备能做的事都一样。架构草案 5.7 写过"手机不能开终端"，但代码里还没有这条。
- **对话框已经有用量**（写方案时）：顶部是模型下拉、思考下拉和一个用量条（↑输入 ↓输出 $ 上下文圆环），每轮回复下面有一行（模型 · 耗时 · ↑↓ · $）。输入框只有文本框和发送键。D1 之后见第 6 节。

【事实】Pi 那边：

- `createAgentSession({ cwd })` 按会话指定工作目录，不必是进程的 cwd。
- 自带工具有 `read`、`bash`、`edit`、`write`、`grep`、`find`、`ls`；`tools` / `excludeTools` 可以按会话开关。
- `bash` 有 `spawnHook`，执行前可以改命令、目录和环境变量。
- Pi 自己的安全文档写明：**模型生成的命令按不可信对待；工作目录只决定发现资源和工具的默认位置，挡不住命令访问别的路径**；真正的边界只有容器、虚拟机或沙箱。

## 2. 两种对话差在哪

| | 日常 | 开发 |
|---|---|---|
| 属于 | 不属于项目 | 一个项目（可选 worktree） |
| 工作目录 | 数据目录 | 项目文件夹或它的 worktree |
| 能力档 | `assistant` 提供待办、日历、邮件等日常模块工具 | `developer` 提供项目文件、终端和进程工具，按会话模式授权；两边都可以向用户提问 |
| 提示里的上下文 | 人设、记忆、你在看哪一页 | 人设、项目的 AGENTS.md / CLAUDE.md、git 状态；不带页面上下文 |
| 权限 | 四级（只读、本地可逆、批量、对外不可逆） | 四级照旧，外加权限模式（第 4.3 节） |
| 回执 | 世界里的领域操作 | 改了哪些文件（+/−）、跑了哪些命令和退出码 |
| 在哪看 | 右侧 Alfred 面板，跟着页面走 | 侧栏「开发」页，整页 |
| 新建 | 直接打字 | 先选项目，再打字 |

为什么不允许中途切换：两种对话的 Pi 会话、工作目录、工具集和授权都不同。中途切换，前几轮在没有 shell 的前提下说的话，会被当成在有 shell 的环境里说的；本会话的命令授权也说不清归谁。需要时用「转成开发会话」（第 4.6 节），开一条新的。

## 3. 通用语言

| 词 | 含义 | 不是什么 |
|---|---|---|
| 项目（Project） | 主节点上登记过的一个文件夹，有名字、路径、信任状态和默认权限模式 | 不是 git 仓库的同义词（不是仓库也能登记），不是某台设备上的路径 |
| 开发会话 | 属于一个项目的对话 | 不是另一种数据结构：它就是 `Conversation`，多了项目字段 |
| 工作树（Worktree） | 为一条开发会话单独检出的 git worktree，在自己的分支上 | 不是默认行为；不建时会话直接在项目文件夹里改 |
| 权限模式 | 开发会话里，改文件和跑命令要不要先问 | 不是能力档：能力档决定有哪些工具，模式决定用之前问不问 |
| 命令授权 | "本会话都允许 `npm test`"这样的授权，只绑定这条会话和这条命令前缀 | 不是全局白名单 |
| 改动 | 这条会话开始以来，工作目录相对基准提交的 git 差异 | 不是模型说"我改了" |

## 4. 方案

### 4.1 项目

【建议】

- 新表 `core_projects`：`id`、`name`、`path`（主节点上的绝对路径）、`trusted_at`、`default_mode`、`created_at`、`archived_at`。
- **登记**：在开发页点「添加文件夹」，Mac 上弹系统的选文件夹窗口（这是设备能力，只有 Mac App 有）。手机和浏览器不能登记，因为它们不能证明路径是谁选的。
- **信任**：第一次在一个项目里开会话时问一次"信任这个文件夹吗"，说明信任的是什么：读它的 AGENTS.md / CLAUDE.md、让模型在里面读写和跑命令。不信任就不能开开发会话。这和 Pi 的 project trust 是一回事，界面上只问一次。
- 项目的 `.pi/settings.json`、`.pi/mcp.json` **不加载**。MCP 照旧只用 Alfred 自己的 `<数据目录>/mcp.json`，免得一个仓库悄悄带进新的工具。

### 4.2 对话多出的字段

【建议】`core_conversations` 加：

| 字段 | 含义 |
|---|---|
| `project_id` | 空 = 日常 |
| `worktree` | 空 = 直接在项目文件夹里；否则是 worktree 的路径 |
| `branch`、`base` | worktree 的分支和开会话时的基准提交（不建 worktree 时也记基准，用来算改动） |
| `mode` | 权限模式，默认取项目的 `default_mode` |

- 开发会话**显式创建**：`POST /api/conversations { projectId, worktree, mode }`，返回 id，第一句话再提交。日常对话照旧在第一次提交时隐式创建。
- 任务的能力档从对话推出来：有 `project_id` 就是 `developer`，否则是 `assistant`。客户端不能自己指定档。
- worktree 建在 `<数据目录>/worktrees/<项目>/<对话 id>`，分支 `alfred/<标题缩写>`，不弄脏仓库本身。归档会话时，worktree 没有未提交的改动才删；有就问。

### 4.3 能力档 `developer` 和权限模式

【建议】工具和它们在三个模式下的处理：

| 工具 | 只读计划 | 操作前询问 | 本次会话始终允许 |
|---|---|---|---|
| `read`、`grep`、`find`、`ls`（工作目录内） | 直接做 | 直接做 | 直接做 |
| 同上，工作目录外 | 问 | 问 | 问 |
| `edit`、`write`（工作目录内） | 禁止执行 | 问，卡片上带 diff | 直接做，记回执 |
| `edit`、`write`（工作目录外） | 禁止执行 | 问 | 问 |
| `bash`、`process_start` | 禁止执行 | 问，可记住单条普通命令，也可切换到「本次会话始终允许」 | 直接执行，包括管道和复合命令 |
| Alfred 的领域工具 | 没有（2026-11-20 改，见下） | 没有 | 没有 |
| MCP（你自己连的） | 和日常相同 | 和日常相同 | 和日常相同 |

- **记住这条命令**在询问模式下按前缀匹配。记住 `npm test` 会放行 `npm test -- foo`。包含管道、重定向或命令连接符的命令仍要询问。
- **本次会话始终允许**可以从输入框的权限菜单、项目内文件修改卡或命令卡选中。选中后即放行当前符合条件的待审批操作，后续回合沿用同一设置。换回询问模式后，下一次操作按询问模式处理。
- 路径判断在拦截扩展里做：先 `realpath`，再看是否在工作目录下，符号链接指出去的算外面。
- 开发会话不带页面上下文：在「待办」页时开着的开发会话，问的不是待办。
- 【2026-11-20 改】开发会话也不带日常的工具和说明：没有待办、日历、邮件、链接这些模块的工具和它们的使用说明，没有提议和自动任务，只留 `ask_user`。说明里写明「这里说的事默认都是这个项目里的」。起因：Bruce 在 bruce-portfolio 里说"把我的生日改成 9 月 21 号"（意思是网站上的），Alfred 反问要改日历、个人资料还是待办，因为它手里有日常那套工具和说明。

### 4.4 引擎的改动

【建议】改动都在 `engine-pi` 里，核心的任务状态机不动：

- `RunJob` 加 `cwd`、`tools`（内置工具的允许表）、`mode`、`contextFiles`。子进程用 `job.cwd` 建会话，不再用进程级的 `--cwd`；`--cwd` 只留给日常对话的默认目录。
- 热会话的 `shape` 哈希加上 `cwd`、能力档和模式。换模式就重开会话，从会话文件继续，不丢上下文。
- 会话文件照旧按对话 id 存在 `engine/sessions/<对话 id>/`，跟着对话走，不放进项目里。
- 拦截扩展 `alfred-gate` 按上表扩展：认识 `edit`、`write`、`bash` 的参数，问的时候把 diff 或完整命令交给主节点。
- 开发会话的系统提示：人设加一段"你在 X 项目里写代码"的说明，再加 AGENTS.md / CLAUDE.md（`noContextFiles: false`，只读工作目录这一层和它的上级，不读 `~/.pi`）。
- **以后**：ACP 适配器（架构草案 5.5）接 Claude Code、Codex，作为新会话页上的「引擎」选项。开发会话是 ACP 最先有用的地方。第一版只用 Pi。

### 4.5 回执：改动和命令

【建议】

- 每轮结束，主节点在工作目录跑 `git diff --numstat <base>` 和 `git status --porcelain`，把这一轮新增的改动记成回执 `files.changed`（文件、+/−）。不是 git 仓库的项目，退回到用拦截扩展记下的 `edit` / `write` 路径。
- 每条 `bash` 记一个步骤，结束时带退出码和耗时；输出只存最后 200 行，完整的留在 Pi 的会话文件里。
- 改动面板读的是**整条会话**相对 `base` 的差异，不是某一轮。点文件看 diff。
- 「提交」「开 PR」是按钮，走现有的"对外不可逆"确认：推送和开 PR 每次都问。

### 4.6 界面

【建议】见原型 `prototype/dev.html`。

**侧栏**：在「模块」下面加一组「开发」，列出项目，项目下是最近的会话（状态点：在做、等你、完成）。收成图标栏时是一个图标，悬停看最近的会话。

**新会话页**（参照 Claude Code 的新会话）：形象在中间，下面依次是

- 选项目：最近用过的项目、「添加文件夹」；
- 两个开关：用 worktree、权限模式；
- 输入框和底栏（模型、思考强度）；
- 下面几条"接着做"：上次没做完的会话、项目里未提交的改动。

> 2026-11-18 改：上面的做法（项目列表、权限模式三张卡片、输入框、最近会话四块叠着）太大太复杂。现在只有一个输入框，项目和权限模式是它底栏里的两个下拉；输入框下面一行小字写项目路径和所选模式的含义；再下面是最近 5 个会话。「添加文件夹」是项目下拉的最后一项。
>
> 开发页（新会话页和会话页）背后有一层缓慢移动的字符（`shell/AsciiField.tsx`），用来和日常页面区分：新会话页上字符绕开中间的内容，会话页上只在阅读栏两侧和顶栏后面很淡地出现。它每秒只画 4 帧，帧与帧之间由浏览器做渐变，所以看起来是连续流动的。系统设了「减少动态效果」时它是静止的；窗口不在前台时也停住。

**会话页**：

- 顶栏：会话标题，项目 · 分支，右边是用量（↑ ↓ $ 上下文圆环，和 pi web 一样一眼可见），以及收放右栏的按钮。
- 中间：对话。工具调用折成一行（"读了 4 个文件"、"跑了 2 条命令"），点开看细节。要你批准的命令和改动是一张卡片，按钮直接在卡片上。
- 底部：输入框，下面一条底栏放附件、模型、思考强度、权限模式、麦克风。
- 右栏：环境（项目、文件夹、分支、在哪台机器上）、上下文（占用多少）、连接器、改动（+/−，文件列表）、后台进程。

**日常对话也换成同一个组件**：顶部只留标题和用量；模型和思考强度从顶部挪到输入框底栏；没有权限模式和右栏。

**转成开发会话**：日常对话里你让 Alfred 改代码时，它没有写文件的工具，于是回一张卡片："这要改代码，在 Alfred 项目里开一个开发会话？"，附一段它写好的说明。点了就建会话、把说明放进输入框，**不自动发出**；你看过再发。

**手机**：开发页是一列。会话列表 → 会话；右栏变成从底部拉出的"详情"。批准命令的卡片照常显示完整命令。

### 4.7 多设备

【建议】

- 设备加一个范围字段 `scopes`。第一个范围是 `dev`：开开发会话、往开发会话里发话、批准开发会话里的改动和命令、看 diff。
- Mac 本机默认有 `dev`。配对设备可以在开发会话页或「设置 → 设备」里申请。Mac 会显示设备名和权限说明，用户可以允许或拒绝。允许后，设备上已打开的会话自动解锁。Mac 的「设置 → 设备」也可以随时更改授权。
- 没有 `dev` 的设备能看到开发会话的标题和状态（侧栏、通知页），不能看内容、不能发话、不能批准。
- 主节点在 HTTP 层检查范围：开发会话的 `submit`、`steer`、`respond`、diff 接口都要 `dev`。
- 吊销设备立即生效，它批准过的"本会话都允许"随之作废。

### 4.8 协议的改动

【建议】

- `GET /api/projects`、`POST /api/projects`（只接受 Mac App 的设备能力发来的路径）、`POST /api/projects/:id/trust`、`DELETE /api/projects/:id`。
- `POST /api/conversations`：显式创建，带 `projectId`、`worktree`、`mode`。`PATCH` 能改 `mode`。
- `GET /api/conversations/:id/changes`（文件和 +/−）、`GET /api/conversations/:id/diff?path=`。
- `StateResponse` 加 `projects`；`Conversation` 加 `projectId`、`branch`、`mode`。
- 新事件：`project.added`、`project.trusted`、`conversation.mode_set`、回执 `files.changed`、步骤 `command`（带退出码）。
- 运行请求 `RunRequest` 的 `permission` 种类加 `detail`：命令全文，或改动的 diff；加一个回答 `allow_session`（本会话都允许）。

### 4.9 按"人始终在控制"重看过程、权限和代码（2026-11-24）

【建议】，**未批准**。依据是 `docs/ARCHITECTURE.md` 第 1 节 2026-11-24 定下的"人始终在控制"和它的三问（知道、决定、撤回）。

> 2026-11-24 展开成单独的设计文档 [in-control.md](in-control.md)（v0.3：产品、地图、决策三样，加上会话里的进度行、底线和回执），[原型](../../prototype/in-control.html)。下面是最初的三点，其中"看改动，不看代码"已被 in-control.md 取代：控制的单位是决定，不是 diff。

**过程：命令默认收起来。**

- 对话里每一步只留一行可点的进度，写意图，不写命令："正在查找首页作品区" → "正在加入三张画"。这一行在原地更新，聊天记录不被命令越推越长。
- 点开这一行才看到命令、输出和 diff。收起的是噪音，不是事实：每条命令、每处改动都在，一次点击就到。
- 一轮结束留一张回执（4.5 节）：改了哪些文件、为什么、怎么验证的、还有什么没验证。

**权限：边界以内不问，越界才问。**

- 逐条"允许一次"不做默认。它让人养成不看就点的习惯，换来的是"在控制"的错觉。
- 边界：项目工作目录。里面的读、改、跑命令直接做，记进回执；会话本身在 worktree 里，退得回。
- 越界的事每次都问：工作目录外的文件、推送和开 PR、删掉未提交的改动、装全局的东西、花钱或对外发消息的服务。问的时候用一句话说后果（"把这三处改动推到公开仓库？"），完整命令放在点开的详情里。
- 三个权限模式可以收成两个：「先给我看计划」（现在的只读计划）和「放手做，越界再问」。逐条询问留作设置里的选项，给想逐条看的人。

**代码：不做 IDE，默认看改动，不看代码。**

- 用户控制项目，靠的不是读每一行，而是随时答得上：项目现在是什么样、agent 改了什么、为什么、能不能退回。
- 所以默认看到的层次是：意图（进度行）→ 改动回执（哪些文件、为什么）→ diff → 整个文件。文件只读，可以一键用用户自己的编辑器打开。
- "接受改动"是人做的决定：合并 worktree、提交、开 PR 都由用户点。agent 的改动在被接受之前只是提议。
- 项目近况：每个项目留一份短的"最近改了什么、定了什么、为什么"，用户回来时先看它，不用翻聊天记录。

**待定（Bruce）：** 逐条询问是删掉还是留作选项；进度行是否也用在日常对话（查日历、读邮件）；项目近况放哪、谁来写。

## 5. 安全

- **工具白名单不是沙箱。** 开发会话里的 shell 用的是你的用户权限：你能读写的文件它都能碰，也能联网。界面上开会话时说一次，文档里写明。
- 文件工具按实际路径判断是否在项目内，修改项目外的文件始终询问。shell 的工作目录是项目目录，命令能访问的资源取决于运行它的系统用户。
- 远程设备默认不能碰开发会话（4.7）。手机被偷了，最多看到会话标题。
- 项目里的文件、代码注释和命令输出只提供上下文。权限来自用户在权限菜单或审批卡上的选择。
- 推送、开 PR、发布都按"对外不可逆"每次确认。
- 不读项目的 `.pi/` 配置，不让仓库自己加工具或 MCP。

## 6. 搭建顺序

每一刀都能单独用。

1. **D1 对话组件**【已实现，2026-11-18】：顶部只留标题和用量（↑ ↓ $ 上下文圆环），模型和思考强度挪到输入框下面的底栏（`Conversation.tsx` 的 `ConversationHead`、`ComposerBar`）。只动界面，日常对话先受益。新对话在第一句话之前还没有对话可存，所以底栏只有发送键。
2. **D2 项目和只读开发会话**【已实现，2026-11-18】：`core_projects`、显式创建对话、子进程按会话的 `cwd`、`developer` 档只开读类工具、读 AGENTS.md。开发页、新会话页、会话页（先没有右栏）。能问"这个仓库怎么组织的"。
   - 核心：`packages/core/src/projects.ts`（添加、信任、移除；路径先 `realpath`）、迁移 `core:9`、`startSession`；执行器按对话给引擎 `workspace`，档和项目对不上（或项目被移除、没信任）的任务直接失败，不进引擎。
   - 引擎：会话在项目文件夹里开；Pi 内置工具加 `grep`、`find`、`ls`；项目里看（符号链接先解析）不问，项目外照旧问（`packages/engine-pi/src/looking.ts`）；2026-11-21 起，用户信任过的其他项目也可以不问就看（只读：read / grep / find / ls），并且会话的指令里列出这些项目的名字和路径，所以"看看我 alfred 的仓库"不用再问在哪；改那里的文件、跑命令仍然每次问，没加进 Alfred 的文件夹仍然每次问；AGENTS.md / CLAUDE.md 用 Pi 的 `loadProjectContextFiles` 读，资源发现仍在 Alfred 自己的目录，项目的 `.pi/` 不加载。Pi 找不到 `fd` / `rg` 时会自己下载。
   - 主节点：`POST /api/projects`、`/api/projects/:id/(trust|remove)` 只接受本机；`POST /api/conversations` 建会话；会话里的任务自动用 `developer` 档，不带页面上下文，也没有 `show_view`。
   - 界面：侧栏「开发」组（项目 → 最近 4 个会话），日常「对话」列表不再列开发会话；「开发」页是新会话页（选项目、添加文件夹、信任卡片、最近会话）或整页会话（返回、项目、"只读"标记）；通知和 ⌘K 打开会话时自动到「开发」页。Mac App 用系统选文件夹窗口（`pick-folder`），本机浏览器里输入路径。
   - 2026-11-18 用真实的 Pi 跑过（模型是 Pi 的默认）：在本仓库里 grep 和 read 不问、回答带 path:line；在一个带 AGENTS.md 的临时项目里，模型不用工具就说出了 AGENTS.md 里的内容；项目里指向外面文件的符号链接被拦下来问，拒绝后不读；ls、find 不问。步骤里项目内的路径从项目根写起（`src/app.ts`），项目外写全路径。
   - 设备范围 `dev` 照第 6 节放到 D4；D2 期间配对的手机能看、能在会话里问，但不能添加或信任项目。
3. **D3 改文件**【已实现，2026-11-18】：`edit` / `write`、三个权限模式、带 diff 的批准卡片、`file.changed` 回执、右栏的改动面板。改动相对开会话时的快照算（`packages/server/src/workspace.ts`：一个不动工作区的 git 提交）。
4. **D4 命令**【已实现，2026-11-19】：`bash`、命令卡片、本会话命令授权、退出码步骤；设备范围 `dev`。
   - 2026-11-22 更新：以下是 D4 上线时的行为。当前会话的权限规则见 4.3，后台命令也遵循同一规则。
   - 规则在 `packages/core/src/shell.ts`：只有"一条普通命令"能被「这个会话里都允许」，授权按前缀算（`npm test` 也放行 `npm test -- foo`）；带 `;`、`&`、`|`、`<`、`>`、反引号、`$(`、`${`、换行的每次都问，也不给这个选项。授权存在对话上（`core_conversations.commands`，`core:13`），记着是哪台设备给的。
   - 引擎：`plan` 模式没有 `bash`；`ask` 和 `edits` 有，闸门对每条命令都问（`edits` 只免问项目内的改文件，不管 shell）。问的时候命令全文作为 `detail`（`detailKind: "command"`），不进事件日志。步骤结束时带退出码、耗时和输出的最后 200 行（上限 8000 字符）。日常对话里没有 shell，核心也会把这种请求直接拒掉。
   - 设备范围：`core_devices.scopes`，`POST /api/devices/:id/scope`（只许本机）。没有 `dev` 的配对设备：`/api/state` 里看得到会话标题和忙不忙，看不到它的任务、步骤、问题；事件流里这些会话的事件只剩空的 payload，流式文字不发；开会话、发话、回答、取消、看改动一律 403 `needs_dev`。吊销设备或关掉它的 `dev`，它给过的「本会话都允许」同时作废。
   - 界面：命令卡片（等宽显示全文，三个按钮）、步骤里每条命令一行（退出码、耗时，点开看输出）、会话右栏「命令」一节列出本会话默许的命令并可撤回、设置 → 设备里每台设备一个「开发会话」开关。
   - 没做的：推送通知的正文对没有 `dev` 的手机没有过滤（问题文字本身不含命令，改文件的问题带文件路径）；还没用真实的 Pi 回合跑过 `bash`（单元测试覆盖了核心和 HTTP，子进程里的闸门没有）。
5. **D5 worktree 和收尾**【已实现，2026-11-20】：建 worktree、归档时清理、提交和开 PR 的按钮、后台进程面板。
   - worktree：新会话页输入框底栏一个「worktree」开关。打开时主节点在 `<数据目录>/worktrees/<项目>/<随机名>` 从项目的 HEAD 检出一个新分支 `alfred/<标题里的英文词>`（中文标题是 `alfred/session`，重名加 `-2`），会话、终端、后台进程都在那里；项目文件夹里没提交的东西不带过去，也不动。对话多两个字段 `worktree`、`branch`（迁移 `core:17`）。不是 git 仓库、或还没有提交的，开不了（`git_not_git`、`git_no_commit`）。
   - 归档：会话的后台进程和终端结束；worktree 干净就删掉文件夹（分支和提交留着）；有没提交的改动就拒绝（409 `git_dirty`，带个数），侧栏弹卡片让你选「留着文件夹」或「删掉改动」。从归档恢复时，worktree 在它的分支上重新检出。侧栏里开发会话也有了归档按钮。
   - 提交：改动面板下「提交」，卡片里列出文件、写说明。只提交这个会话改动列表里的文件（`git add -A -- <这些>` 再 `git commit -- <这些>`，你自己暂存的别的东西不进去）；钩子失败照原样报出 git 的话。提交后改动从新的快照算起，面板清空。
   - 开 PR：「开 PR」卡片先写明要发什么到哪（把分支推到 origin、开一个合并到主分支的 PR），每次都要点；推送用 `git push -u origin`，PR 用 `gh pr create`。已有打开的 PR 时按钮变成「推送」。在主分支上、没有 origin、没装或没登录 gh 时不发，说原因。面板一行写「N 个提交没推送」和 PR 链接。
   - 后台进程（`packages/server/src/processes.ts`）：Alfred 用 `process_start` 起（跟 bash 一样把命令整条给你看、先问，「本会话都允许」的命令不问；plan 模式没有），`process_list`、`process_logs`、`process_stop` 不问。你也可以在面板底下输入一条命令起一个（只在本机，和终端一样）。用登录 shell 跑、自成进程组，停的时候连它起的子进程一起停；主节点停了它们都停。输出留最后 256 KB；打印出的本机地址（`0.0.0.0`、`[::]` 当作 localhost）在面板上可点，Mac App 里在浏览器窗格里打开。每个会话最多 8 个在跑，全部最多 24 个；进程不进世界，主节点重启后列表是空的。
   - 验证：`packages/server/test/worktree.test.ts` 四个测试；在临时主节点上用浏览器看过新会话页的开关、面板的提交（真的提交进 worktree）、进程和它的输出，中英、手机宽度。没验证的：对真实 GitHub 推送和开 PR（只测了"没有 origin"被拦下）；真实模型调用 `process_start`。
